# /study — 기술 학습 정리

기술 스택, 개념, 도구를 대화를 통해 깊이 정리하고 `Study/`에 문서로 저장한다.

## Steps

### Phase 1: 대화 시작

1. 아래 안내 메시지로 시작:
   > 학습 정리를 시작합니다. 어떤 기술이나 개념을 공부하셨나요?
   > 알고 있는 것, 헷갈리는 것, 궁금한 것 자유롭게 이야기해주세요.
   > 마무리하려면 `정리해줘` 라고 말씀해주세요.

2. 사용자가 주제를 말하면 **심층 질문**으로 대화를 이끈다:
   - 개념의 핵심 원리를 이해했는지 확인하는 질문
   - 실제로 어떻게 쓰는지, 언제 쓰는지 묻는 질문
   - 비슷한 개념/기술과의 차이점 질문
   - 왜 이렇게 설계됐는지, 트레이드오프 질문
   - 실수하기 쉬운 부분이나 주의사항 질문
   - 실제 프로젝트에서 써봤거나 쓸 계획이 있는지 질문

3. **대화가 충분히 쌓이면** (또는 사용자가 `정리해줘` 입력 시) Phase 2로 전환.

---

### Phase 2: 문서화 (`정리해줘` 입력 시 실행)

1. **주제 확정**
   - "주제를 어떻게 잡을까요? 직접 입력하시거나 '알아서 해봐' 라고 하시면 제가 정할게요."
   - 사용자가 직접 입력 → 그대로 사용
   - '알아서 해봐' → 기술명/개념명 기반으로 추출

2. **파일명 생성**
   ```
   Study/YYYY-MM-DD-<주제>.md
   ```
   예: `Study/2026-03-30-React-Query-캐싱전략.md`

3. **문서 작성** — 아래 템플릿으로 작성:

```markdown
# <주제>

> <날짜> | <태그 1-3개>

## 한 줄 요약

<이 기술/개념을 한 문장으로>

## 핵심 개념

<개념의 원리, 동작 방식을 디테일하게 — 피상적 설명 금지>

## 언제 쓰나

- <이럴 때 사용>
- <이럴 때는 쓰지 않는 게 낫다>

## 사용법 / 예제

```코드 or 예시```

## 비슷한 것과의 차이

| | <A> | <B> |
|--|--|--|
| 특징 | | |
| 적합한 상황 | | |

(비교 대상이 없으면 생략)

## 핵심 질의응답

대화에서 나온 핵심 포인트를 Q&A 형태로 정리:

**Q. <질문>**
A. <답변 / 깨달은 점>

**Q. <질문>**
A. <답변 / 깨달은 점>

(대화에서 나온 인사이트 수만큼 추가)

## 주의사항 / 자주 하는 실수

- <이런 점 조심>

## 참고

- <링크 or 문서>
```

4. **사용자에게 초안 보여주고 확인** — "이렇게 정리했는데 수정할 부분 있나요?"

5. **확인 후 커밋/PR/머지**:
   ```bash
   git checkout main && git pull origin main
   git checkout -b study/<날짜>-<주제슬러그>
   git add Study/<파일명>.md
   git commit -m "docs(study): <주제>

   Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>"
   git push -u origin study/<브랜치명>
   gh pr create --title "docs(study): <주제>" --body "<문서 요약 2-3줄>"
   gh pr merge --squash --delete-branch
   git checkout main && git pull origin main
   ```

## Rules

- **개념 설명은 디테일하게** — "편리하다", "빠르다" 수준의 피상적 요약 금지
- 핵심 질의응답은 대화에서 실제로 나온 내용 기반으로 작성 (만들어 내지 않음)
- 비교표는 실질적인 차이가 있을 때만 포함
- 문서 초안은 반드시 사용자에게 보여주고 승인 후 커밋
- 항상 `Work` 레포의 `Study/` 폴더에 저장
