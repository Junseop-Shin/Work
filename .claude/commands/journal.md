# /journal — 업무 회고 저널 작성

업무 경험, 사건, 배운 점을 대화를 통해 정리하고 `Work_History/`에 문서로 저장한다.

## Steps

### Phase 1: 대화 시작

1. 아래 안내 메시지로 시작:
   > 업무 회고 저널을 시작합니다. 자유롭게 이야기해주세요.
   > 어떤 상황이나 사건을 기록하고 싶으신가요?
   > 마무리하려면 `정리해줘` 라고 말씀해주세요.

2. 사용자가 이야기를 시작하면 **적극적으로 질문**하며 대화를 이끈다:
   - 배경/맥락을 이해하기 위한 질문
   - 핵심 사건이나 문제를 파악하는 질문
   - 본인이 한 행동과 의사결정 과정 질문
   - 결과와 그로부터 얻은 인사이트 질문
   - 다음번엔 어떻게 다르게 할 것인지 질문

3. **대화가 충분히 쌓이면** (또는 사용자가 `정리해줘` 입력 시) Phase 2로 전환.

---

### Phase 2: 문서화 (`정리해줘` 입력 시 실행)

1. **주제 확정**
   - "이 내용의 주제를 어떻게 잡을까요? 직접 입력하시거나 '알아서 해봐' 라고 하시면 제가 정할게요."
   - 사용자가 직접 입력 → 그대로 사용
   - '알아서 해봐' → 대화 내용에서 핵심 주제 추출

2. **파일명 생성**
   ```
   Work_History/YYYY-MM-DD-<주제>.md
   ```
   예: `Work_History/2026-03-30-레거시-마이그레이션-회고.md`

3. **문서 작성** — 아래 템플릿으로 작성:

```markdown
# <주제>

> <날짜> | <태그 1-3개>

## 배경

<어떤 상황이었는지 간략히>

## 무슨 일이 있었나

<사건의 흐름, 핵심 문제>

## 내가 한 것

<의사결정 과정, 실제 행동>

## 결과

<어떻게 됐는지>

## 핵심 질의응답

대화에서 나온 핵심 포인트를 Q&A 형태로 정리:

**Q. <질문>**
A. <답변 / 깨달은 점>

**Q. <질문>**
A. <답변 / 깨달은 점>

(대화에서 나온 인사이트 수만큼 추가)

## 다음번엔

- <이렇게 하겠다 / 이런 점을 주의하겠다>
```

4. **사용자에게 초안 보여주고 확인** — "이렇게 정리했는데 수정할 부분 있나요?"

5. **확인 후 커밋/PR/머지**:
   ```bash
   # Work 레포 기준
   git checkout main && git pull origin main
   git checkout -b journal/<날짜>-<주제슬러그>
   git add Work_History/<파일명>.md
   git commit -m "docs(journal): <주제>

   Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>"
   git push -u origin journal/<브랜치명>
   gh pr create --title "docs(journal): <주제>" --body "<문서 요약 2-3줄>"
   gh pr merge --squash --delete-branch
   git checkout main && git pull origin main
   ```

## Rules

- 단순 요약이 아니라 **질의응답을 통해 깨달은 점**이 문서에 드러나야 한다
- 회사/고객 이름 등 민감한 정보는 익명 처리 (사용자가 명시적으로 써도 된다고 하지 않는 한)
- 문서 초안은 반드시 사용자에게 보여주고 승인 후 커밋
- 항상 `Work` 레포의 `Work_History/` 폴더에 저장
