## 1. 요약정리

### SQL 분류 (DDL/DML/DCL/TCL)
| 분류 | 목적 | 대표 명령어 |
|---|---|---|
| DDL(정의어) | 테이블/스키마 구조 정의 | CREATE, ALTER, DROP, RENAME, TRUNCATE |
| DML(조작어) | 데이터 조작 | SELECT, INSERT, UPDATE, DELETE |
| DCL(제어어) | 권한 부여/회수 | GRANT, REVOKE |
| TCL(트랜잭션제어) | 트랜잭션 확정/취소 | COMMIT, ROLLBACK, SAVEPOINT |

- **DROP vs TRUNCATE vs DELETE**: DROP(테이블 자체를 구조+데이터 통째로 삭제, DDL) / TRUNCATE(테이블 구조는 남기고 그 테이블의 데이터 전체만 삭제, DDL이라 **롤백 불가**) / DELETE(조건(WHERE)별로 행 선택 삭제 가능, DML이라 **롤백 가능**) — 구분축은 "구조까지 지우나 / 데이터 전체만 지우나 / 조건별로 지우나"와 "롤백 가능 여부"

### 제약조건(Constraint)
- PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK
- **PRIMARY KEY vs UNIQUE**: PK는 테이블당 1개만 지정 가능 + NOT NULL 강제. UNIQUE는 여러 개 지정 가능 + NULL 허용(단, 값이 있으면 유일해야 함)

### JOIN
| 종류 | 설명 |
|---|---|
| INNER JOIN | 양쪽 테이블에 조건이 일치하는 행만 |
| LEFT OUTER JOIN | 왼쪽 테이블 기준 전체 + 일치하는 오른쪽 값(없으면 NULL) |
| RIGHT OUTER JOIN | 오른쪽 테이블 기준 전체 |
| FULL OUTER JOIN | LEFT OUTER JOIN + RIGHT OUTER JOIN의 합집합(양쪽 다 놓치지 않고 포함, 조인 조건은 그대로 존재) |
| CROSS JOIN | 조인 조건 없이 두 테이블의 모든 조합(카티션 곱, M×N개) |
| SELF JOIN | 같은 테이블을 별칭으로 자기 자신과 조인 |

- **FULL OUTER JOIN ≠ CROSS JOIN**: CROSS JOIN은 조건 자체가 없어 결과가 M×N으로 폭증하지만, FULL OUTER JOIN은 조인 조건은 유지한 채 "양쪽 다 놓치지 않고 포함"하는 것

### 집계함수 & GROUP BY/HAVING
- COUNT, SUM, AVG, MAX, MIN
- **WHERE vs HAVING**: WHERE는 그룹화 이전 개별 행 필터링(집계함수 사용 불가), HAVING은 그룹화 이후 그룹 단위 필터링(집계함수 조건 가능) — "처리 시점"이 핵심 구분

### 서브쿼리
- 단일행 서브쿼리(=, <, >) vs 다중행 서브쿼리(IN, ANY, ALL)
- **IN**: 목록 중 하나와 일치하면 참(OR 조건의 합)
- **ANY(=SOME)**: 비교연산자와 함께 사용, 서브쿼리 결과 중 하나라도 조건을 만족하면 참(예: `> ANY`는 최솟값보다 크면 참)
- **ALL**: 서브쿼리 결과 모두가 조건을 만족해야 참(예: `> ALL`은 최댓값보다 커야 참)
- **상관 서브쿼리(Correlated Subquery) vs 일반 서브쿼리**: 일반 서브쿼리는 독립적으로 한 번만 실행되어 결과를 외부에 전달. 상관 서브쿼리는 내부 쿼리가 **외부 쿼리의 컬럼을 참조**하고 있어서 외부 쿼리의 **각 행마다 반복 실행**됨
- **EXISTS**: 서브쿼리 결과가 존재하는지(1건 이상)만 확인, 실제 값 자체는 신경 쓰지 않음

### 윈도우 함수
- `OVER(PARTITION BY ... ORDER BY ...)` 구문으로 그룹별 순위/누적 계산
- RANK(동순위 시 다음 순위 건너뜀, 1,1,3,4,5) vs DENSE_RANK(건너뛰지 않음, 1,1,2,3,4) vs ROW_NUMBER(동순위 없이 고유 순번, 1,2,3,4,5)

### 뷰(VIEW) & 인덱스(INDEX)
- **뷰**: 장점은 ① 보안(특정 컬럼/행만 노출) ② 편의성(복잡한 쿼리 재사용). 단점은 인덱스를 직접 가질 수 없고, 조인으로 만든 뷰는 삽입/삭제/갱신(DML)에 제약이 있음
- **인덱스**: 대표 구조 B-Tree — 하나의 노드가 여러 키를 가지는 **다지(multi-way) 균형 트리**로, 모든 리프 노드가 항상 같은 깊이에 있어 탐색이 O(log n)으로 보장되고 디스크 I/O(노드 접근 횟수)가 최소화됨(이진 트리의 "이분 탐색"과는 다른 개념)
- 인덱스 트레이드오프: **조회(SELECT)는 빨라지지만, 인덱스 자체도 갱신돼야 하므로 삽입/삭제/갱신은 느려지고 저장 공간도 추가로 필요**

### 트랜잭션 특성(ACID)
| 특성 | 의미 |
|---|---|
| 원자성(Atomicity) | 전부 실행되거나 전부 실행 안 되거나 |
| 일관성(Consistency) | 트랜잭션 전후로 항상 무결성 규칙을 만족하는 상태 유지 |
| 고립성(Isolation) | 동시 실행 트랜잭션끼리 서로 간섭 없음 |
| 지속성(Durability) | 커밋된 결과는 영구 반영 |

- **COMMIT vs ROLLBACK**: COMMIT은 변경사항을 영구 확정, ROLLBACK은 변경사항을 취소하고 이전(또는 SAVEPOINT) 상태로 되돌림
- **SAVEPOINT**: 트랜잭션 중 특정 지점에 이름을 지정해두고, 오류 발생 시 전체가 아니라 그 지점까지만 부분 롤백(`ROLLBACK TO SAVEPOINT`)할 수 있게 하는 기능. 커밋과는 무관

### 절차형 SQL
- **프로시저(Procedure)**: `CALL`/`EXECUTE`로 명시적 호출, 반환값 없어도 됨(OUT 파라미터로 여러 값 전달 가능), 트랜잭션 제어문(COMMIT/ROLLBACK) 포함 가능
- **함수(Function)**: 반드시 하나의 값을 RETURN, `SELECT` 문 안에서 표현식처럼 호출 가능, 일반적으로 트랜잭션 제어 불가
- **트리거(Trigger)**: 특정 이벤트(INSERT/UPDATE/DELETE) 발생 시 자동 실행, 명시적 호출 불가

### 정규화(Normalization)
- 목적: 데이터 중복 최소화 + 삽입/삭제/갱신 시 발생하는 **이상현상(Anomaly)** 방지 → 데이터 무결성 유지

### DDL 기타
- **ALTER**로 할 수 있는 작업: 컬럼 추가(`ADD COLUMN`), 컬럼 삭제(`DROP COLUMN`), 컬럼 타입/제약조건 변경(`MODIFY`/`ALTER COLUMN`) — 데이터가 아니라 스키마(구조) 자체를 수정한다는 점에서 UPDATE와 구분

## 3. 해설

1. **정답: DROP(테이블 구조+데이터 통째로 삭제, DDL) / TRUNCATE(테이블 구조는 남기고 데이터 전체만 삭제, DDL이라 롤백 불가) / DELETE(조건별 행 삭제 가능, DML이라 롤백 가능)**. "연관 테이블 전체 삭제"로 답해 TRUNCATE를 잘못 설명함(연관 테이블 개념 아님, 그 테이블 자신의 데이터 전체 삭제). 핵심 구분축은 "구조까지/데이터 전체만/조건별"과 "롤백 가능 여부".

2. **정답 그대로**. WHERE는 그룹화 이전 개별 행 필터링(집계함수 불가), HAVING은 그룹화 이후 그룹 단위 필터링(집계함수 조건 가능).

3. **정답: 일반 서브쿼리는 독립적으로 한 번만 실행되어 결과를 외부에 전달, 상관 서브쿼리는 외부 쿼리의 컬럼을 참조해 외부 쿼리의 각 행마다 반복 실행됨**. "조건문에 들어가는가 아닌가"로 답했으나 둘 다 조건문에 들어갈 수 있음 — 진짜 차이는 "실행 방식(1회 vs 행마다 반복)".

4. **정답 그대로**. RANK(1,1,3,4,5, 동순위 다음 건너뜀) vs DENSE_RANK(1,1,2,3,4, 안 건너뜀) vs ROW_NUMBER(1,2,3,4,5, 동순위 없이 고유 순번).

5. **모범답안**: 장점 ① 보안(특정 컬럼만 노출) ② 편의성(재사용, 답변에 포함). 단점: 인덱스를 직접 가질 수 없고, 조인 기반 뷰는 삽입/삭제/갱신에 제약. "파싱 안 되어 느림", "디버깅 어려움"은 표준 키워드가 아님.

6. **모범답안**: 프로시저는 `CALL`/`EXECUTE`로 명시적 호출하고 반환값 없어도 됨, 함수는 반드시 하나의 값을 RETURN하며 `SELECT` 문 안에서 호출 가능. 답변("프로시저는 트랜잭션 제어/에러처리 가능, 함수는 불가")도 실제로 맞는 차이지만, 가장 많이 채점되는 포인트는 "호출 방식 + 반환값".

7. **정답: 원자성(Atomicity), 일관성(Consistency), 고립성(Isolation), 지속성(Durability)**. "동시성"이라고 답해 일관성 대신 잘못된 용어를 씀. 고립성 정의("트랜잭션 간 영향 없이 분리")는 정확했음.

8. **정답: 조회(SELECT)는 빨라지지만, 삽입/삭제/갱신은 느려지고 저장 공간도 추가로 필요**. 비용(단점) 쪽만 답하고 이득(조회 속도 향상) 쪽이 빠짐 — "트레이드오프"는 양쪽 방향을 다 언급해야 완전한 답.

9. **정답 그대로**. INNER JOIN은 조건 일치 행만, LEFT OUTER JOIN은 왼쪽 테이블 기준 전체 + 일치 안 하면 NULL.

10. **정답 그대로**. GRANT(권한 부여) / REVOKE(권한 회수), DCL 명령어.

11. **정답 그대로**. CROSS JOIN(조건 없는 모든 조합, 카티션 곱) / SELF JOIN(같은 테이블을 별칭으로 자기 자신과 조인).

12. **정답: ANY/ALL은 비교연산자와 함께 사용. ANY는 서브쿼리 결과 중 하나라도 만족하면 참(`> ANY`=최솟값보다 크면 참), ALL은 모두 만족해야 참(`> ALL`=최댓값보다 커야 참)**. "배열 원소 포함 여부"로 답해 IN과 혼동함 — ANY/ALL의 핵심은 "비교 대상이 하나(ANY)냐 전체(ALL)냐".

13. **정답: 데이터 중복 최소화 + 삽입/삭제/갱신 시 발생하는 이상현상(Anomaly) 방지 → 데이터 무결성 유지**. "꼬이는 문제"로 답해 방향은 맞았으나 공식 용어(이상현상, Anomaly)가 빠짐.

14. **정답: LEFT OUTER JOIN + RIGHT OUTER JOIN의 합집합, 양쪽 테이블의 모든 행을 포함하되 일치 안 하는 쪽은 NULL로 채움**. "CROSS JOIN과 같은 것 아니냐"고 답했으나 전혀 다른 개념 — CROSS JOIN은 조건 자체가 없어 M×N으로 폭증하고, FULL OUTER JOIN은 조인 조건을 유지한 채 양쪽을 다 포함.

15. **정답 그대로**. 서브쿼리 결과의 존재 여부(1건 이상)만 확인, 값 자체는 무의미.

16. **정답 그대로**. COMMIT(영구 확정) / ROLLBACK(취소하고 이전 상태로 복귀).

17. **정답: PK는 테이블당 1개만 가능 + NOT NULL 강제, UNIQUE는 여러 개 가능 + NULL 허용**. "로우를 대표하는가"로 답했으나 시험 채점 포인트는 "개수 제한"과 "NULL 허용 여부".

18. **정답: 컬럼 추가(ADD COLUMN), 컬럼 삭제(DROP COLUMN), 컬럼 타입/제약조건 변경(MODIFY/ALTER COLUMN)**. ALTER는 DDL로 테이블 구조(스키마) 자체를 수정.

19. **정답: 트랜잭션 중 특정 지점에 이름을 지정해두고, 오류 시 전체가 아니라 그 지점까지만 부분 롤백하는 기능(커밋과 무관)**. "롤백/커밋의 기준"이라고 답했으나 SAVEPOINT는 커밋과 관련 없고 오직 부분 롤백 지점.

20. **정답: B-Tree는 이진 트리가 아니라 다지(multi-way) 균형 트리 — 모든 리프 노드가 같은 깊이에 있어 탐색이 O(log n)으로 보장되고, 노드 하나에 여러 키를 담아 디스크 I/O를 최소화**. "바이너리 트리 이분 탐색"으로 답해 이진 탐색(Binary Search)과 B-Tree(다지 균형 트리)를 혼동함.

## 4. 반복 오답 패턴 (D-2 최종 암기 시 재확인)

- DDL(DROP/TRUNCATE) vs DML(DELETE) — **롤백 가능 여부**가 핵심 채점 포인트
- 상관 서브쿼리 vs 일반 서브쿼리 — "조건문 안에 있냐"가 아니라 "외부 행마다 반복 실행되냐"
- ANY/ALL — 비교연산자와 결합, 최솟값(ANY)/최댓값(ALL) 개념 (IN과 혼동 주의)
- **FULL OUTER JOIN ≠ CROSS JOIN** (조인 조건 유무가 결정적 차이)
- PRIMARY KEY vs UNIQUE — 개수 제한(1개 vs 여러개) + NULL 허용 여부
- SAVEPOINT는 부분 롤백 지점(커밋과 무관)
- B-Tree는 이진 트리가 아니라 균형 다지 트리(디스크 I/O 최소화 목적) — 이진 탐색과 혼동 주의
- ACID를 쓸 때 "동시성"을 "일관성"으로 착각하지 말 것
