# 스폿 VM과 CI 러너

실무 질문이다. 스폿 VM을 GitHub Actions self-hosted runner로 쓸 때 챙길 것을 정리했다. 스폿 VM 자체는 [컴퓨팅 1](../컴퓨팅-1.md)에 있다.

CI 빌드와 테스트는 중간에 끊겨도 다시 돌리면 되고 작업이 있을 때만 러너가 필요해서 스폿과 잘 맞는다.

| 챙길 것 | 내용 |
|---|---|
| 끊기면 job 실패 | 러너가 회수되면 GitHub Actions는 그 job을 실패로 처리하고 자동으로 다시 돌리지 않는다. 재실행 설정이나 습관이 필요하다 |
| 배포는 일반 VM에 | 배포가 중간에 끊기면 일부만 바뀐 상태가 남는다. 빌드·테스트는 스폿 러너, 배포는 종량제 VM 러너로 라벨을 나눈다 |
| 일회용 러너 | job 하나 끝나면 지워지는 ephemeral 러너로 두면 회수돼도 정리할 게 없다 |
| 확장 구성 | 스폿 VMSS를 대기 job 수에 맞춰 늘리고 줄인다. 쿠버네티스를 쓰면 AKS 스폿 노드 풀에 Actions Runner Controller를 올린다 |
| 대체 경로 | 스폿 자리가 부족해 회수가 잦으면 일반 VM으로 넘어가는 경로를 둔다 |
