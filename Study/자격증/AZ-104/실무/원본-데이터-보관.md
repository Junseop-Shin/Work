# 원본 데이터 보관: Table, Blob, ADLS Gen2

실무 질문이다. 센서 원본 데이터를 Table Storage에 쌓다가 Blob에 Parquet으로 옮기는 중일 때 어디에 두는 게 맞는지 정리했다.

## Table Storage와 파일 저장소

| | Table Storage | Blob·ADLS Gen2 |
|---|---|---|
| 형태 | 키-값 NoSQL, 행 단위 | 파일(CSV, JSON, Parquet) |
| 잘하는 조회 | PartitionKey와 RowKey로 특정 행 찾기. 예: 센서 A의 최근 값 | 몇 달치를 통째로 읽어 집계하기 |
| 못하는 것 | 집계, 정렬. 키가 아닌 컬럼으로 찾으면 전체를 훑는다 | 행 하나를 빠르게 찾기 |
| 저장 비용 | 계층이 없다 | Hot, Cool, Cold, Archive로 옮기면 오래된 데이터가 싸진다 |
| 한도 | 엔터티 1MB, 속성 255개 | 파일 하나 수 TB |

최근 값 조회와 대시보드는 Table Storage나 Cosmos DB, 시계열 DB가 맞고, 원본 전체 보관과 장기 분석은 날짜 폴더(`raw/sensor/2026/11/02/`)에 Parquet으로 쌓는 쪽이 맞다. 오래된 파일은 수명 주기 규칙으로 Cool이나 Archive로 넘긴다.

## Blob에 Parquet과 ADLS Gen2의 차이

읽어서 집계하는 속도는 거의 같다. 파일 형식과 읽는 방식이 같고, 날짜 폴더로 필요한 파일만 고르는 것도 둘 다 된다. 차이는 폴더를 옮기거나 덮어쓰는 쓰기에서 난다.

| 쓰기 방식 | 일반 Blob | ADLS Gen2 |
|---|---|---|
| 새 파일을 날짜 폴더에 추가 | 충분하다 | 차이 없다 |
| 날짜 폴더를 다시 계산해 통째로 덮어쓰기 | 파일마다 복사·삭제라 느리고, 실패하면 반쯤 바뀐 상태가 남는다 | 폴더 이름 변경 한 번이라 빠르고 안전하다 |
| 작은 파일을 큰 파일로 합치기(컴팩션) | 같은 문제 | 유리하다 |
| Spark, Databricks로 저장 | 임시 폴더에 쓴 뒤 이름을 바꾸는 방식이라 불리하다 | 권장 환경이다 |
| 폴더 단위 권한 | 안 된다 | ACL로 된다 |

새 파일을 추가만 하고 DuckDB, pandas, Polars로 읽는다면 지금 Blob으로 충분하다. 지난 데이터를 보정해 다시 쓰거나, 컴팩션을 돌리거나, Spark 계열을 붙이게 되면 ADLS Gen2로 업그레이드한다. 업그레이드는 되돌릴 수 없고 일부 Blob 기능이 제한되므로 지금 쓰는 기능이 지원되는지 먼저 확인한다. 저장 단가는 같고 거래 요금 구조만 조금 다르다.
