## 1. 요약정리

### [D-13] 소프트웨어 개발 보안 구축

**암호화 알고리즘**
| 구분 | 특징 | 예시 |
|---|---|---|
| 대칭키(비밀키) | 암/복호화에 **같은 키**, 속도 빠름, 키 분배가 문제 | DES, AES, SEED, ARIA |
| 비대칭키(공개키) | **공개키/개인키 쌍**, 키 분배 문제 해결, 속도 느림 | RSA, ECC |
| 해시함수 | **단방향**(복호화 불가), 무결성 검증용 | SHA-256(안전), MD5(충돌 취약) |

- **전자서명**: 개인키로 서명 → 공개키로 검증 (부인방지+무결성+인증). 암호화(공개키로 암호화→개인키로 복호화)와 키 사용 방향이 반대
- **PKI**: 인증기관(CA)이 공개키를 인증서로 발급해 신뢰 구축
- **접근통제 모델**: DAC(소유자가 권한 부여) / MAC(시스템이 보안등급으로 강제 결정) / RBAC(역할에 권한 부여, 관리 용이)
- **주요 웹 취약점**: SQL Injection(입력값=데이터/코드 미구분이 근본원인), XSS(악성 스크립트 삽입 실행), CSRF(쿠키 자동 첨부를 악용한 요청 위조, SameSite 속성으로 완화)
- **시큐어 코딩**: 입력 데이터 검증이 대부분 취약점의 1차 방어선
- **최소 권한 원칙**: 업무에 필요한 최소한의 권한만 부여
- 스니핑(수동 도청) vs 스푸핑(능동 위장) / 세션 하이재킹(인증된 세션 탈취) / 랜섬웨어(데이터 암호화 후 금품 요구)
- VPN: 공용망 위에 **암호화된 터널**을 만들어 사설망처럼 안전하게 통신
- 방화벽: 규칙 기반으로 트래픽 허용/차단 / DDoS: 봇넷으로 분산+대량 트래픽 전송해 서비스거부 유발
- OWASP = Open Web Application Security Project (Top 10으로 유명, 시험은 2021년판 용어 기준 가능성 높음)

### [D-12] 응용SW 기초기술 활용 (신기술 단답 암기)

- **OS 스케줄링**: FCFS(도착순, 호위효과로 평균대기시간 증가) / SJF(짧은 작업 우선) / RR(동일 시간할당량을 순서대로, 선점형) / 우선순위(기아현상 발생 가능 → Aging으로 해결)
- **메모리 관리**: 페이징(고정크기, 내부단편화) / 세그멘테이션(가변크기, 외부단편화) / 가상메모리(물리메모리보다 큰 프로그램 실행+멀티프로그래밍 목적)
- **프로세스 vs 스레드**: 프로세스=독립 메모리공간, 스레드=코드/데이터/힙 공유+스택/레지스터만 개별
- **교착상태 4조건**: 상호배제, 점유와 대기, 비선점, 순환대기 (모두 동시 성립해야 발생)
- **네트워크**: OSI 3계층=라우팅/IP주소, 4계층(전송)=TCP(연결지향/신뢰성)·UDP(비연결지향/빠름). DNS=도메인→IP 변환
- **클라우드**: IaaS(인프라만)/PaaS(플랫폼까지)/SaaS(완성 SW) — 관리 범위가 점점 줄어드는 순서
- **컨테이너 vs VM**: VM=게스트OS 통째로(무거움), 컨테이너=호스트 커널 공유(가벼움)
- **빅데이터 3V**: Volume/Velocity/Variety / **블록체인**: 블록을 해시로 연결+분산 저장, 위변조 방지
- IoT: 사물 간 자율적 데이터 통신이 핵심(사람 개입 없이) / 엣지컴퓨팅: 데이터 발생 지점 근처에서 처리(지연시간 단축) vs 클라우드(중앙집중)
- 과적합(Overfitting): 훈련 데이터 성능↑ but 새 데이터 성능↓(일반화 실패) / RPA: UI 레벨 반복업무 자동화
- 캐시 메모리: CPU-주기억장치 속도차 해소(참조지역성 활용) / HTTPS: 암호화+인증서(신원확인), "접근제한" 개념 아님

### [D-11] 제품SW 패키징 / 애플리케이션 테스트 관리

- 릴리즈 노트: 버전정보+신규기능+개선사항+버그픽스+알려진이슈 / DRM: 저작권 보호, 허가된 사용자만 이용 가능하게 함
- 테스트 케이스 구성요소: 식별자, 입력값, 실행조건, 예상결과 ("누가"는 해당 없음)
- 단위테스트(최소단위 개별검증) vs 통합테스트(여러 모듈 결합 시 인터페이스/상호작용 검증)
- 회귀테스트: 변경 후 **기존 기능이 안 망가졌는지** 재확인 / 스모크테스트: 새 빌드가 정밀테스트할 가치가 있는지 핵심기능만 빠르게 확인(사전 관문, 회귀테스트와 목적·시점이 다름)
- 인수테스트: 사용자(고객) 관점에서 검증 / 시스템테스트: 통합된 전체 시스템이 요구사항(기능+비기능) 충족하는지 검증
- 버전 넘버링: Major(대규모 변경).Minor(기능추가).Patch(버그수정)
- 스텁(하위모듈 대체, 하향식) vs 드라이버(상위모듈 대체, 상향식) / 테스트 오라클: 예상 결과 판단 근거
- 결함 관리 프로세스: 등록 → 담당자 할당 → 원인분석·수정 → 재테스트(확인) → 종료
- 소프트웨어 품질 6대 특성: 기능성/신뢰성/사용성/효율성/유지보수성/이식성 (ISO/IEC 25010은 +호환성/보안성 8대)
- 형상관리 항목: 소스코드뿐 아니라 요구사항명세서/설계문서/테스트문서/매뉴얼 등 산출물 전체
- 베이스라인(Baseline): 공식 승인되어 이후 변경 통제의 기준이 되는 형상 항목 버전
- 설치매뉴얼(환경구성 방법) vs 사용자매뉴얼(기능 사용 방법)
- 결정테이블: 조건 조합별 결과를 표로 정리해 조합 누락 없이 테스트케이스 도출(블랙박스)
- 경계값분석: 입력조건의 경계(최솟값/최댓값 부근)에서 오류확률 높다는 점에 착안, 동치분할과 짝으로 출제
- 구문 커버리지(모든 라인 1회 이상 실행) vs 분기 커버리지(모든 조건문 참/거짓 분기 각각 실행, 더 엄격)

## 3. 해설

### 보안(D-13)
1. **정답: 비대칭키는 암호화는 상대방의 공개키, 복호화는 그 개인키로 수행(대칭키는 하나의 키로 양쪽 다)**. "공개키로 복호화"라고 반대로 답함 — 전자서명(개인키 서명→공개키 검증)과 혼동 주의.
2. **정답 그대로**. 단방향이라 복호화 불가, 무결성 검증 용도.
3. **정답 그대로**. 개인키는 본인만 소유하므로 서명을 부인할 수 없음.
4. **정답 그대로**. DAC=소유자가 권한 부여, MAC=시스템이 보안등급으로 강제 결정.
5. **정답 그대로**. 역할에 권한을 묶어 관리 용이.
6. **정답 그대로**. 입력값(데이터)과 SQL 코드를 구분하지 않고 처리하는 것이 근본 원인.
7. **정답: CSRF는 브라우저가 저장된 쿠키를 자동으로 요청에 첨부하는 특성을 악용**. "캐싱", "다른 탭" 표현이 부정확함 — SameSite 쿠키 속성으로 완화 가능.
8. **정답 그대로**. 대부분의 웹 취약점 방어의 1차 방어선.
9. **정답: 둘 다 대칭키 블록 암호**. "공개키/비밀키"로 애매하게 답해 틀림 — SEED(국내표준)/AES(국제표준) 모두 대칭키.
10. **정답 그대로**. 심각도(영향 크기)와 우선순위(처리 시급성)는 다른 축. 반대 예시(오타=낮은 심각도+높은 우선순위)도 기억.
11. **정답: Open Web Application Security Project, OWASP Top 10이 업계 표준처럼 인용됨**. 몰라서 답 못함.
12. **정답 그대로**. 인증=신원확인, 인가=권한확인, 인증이 항상 먼저.
13. **정답: 스니핑=수동 도청, 스푸핑=능동 위장(주소 위조)**. 몰라서 답 못함.
14. **정답 그대로**. 파일 암호화 후 복호화 키를 대가로 금품 요구.
15. **정답 그대로**.
16. **정답: 공용망 위에 암호화된 터널을 만들어 사설망처럼 통신**. "차단된 공간/우회"로 답해 터널링+암호화라는 핵심 메커니즘이 빠짐.
17. **정답: 복잡한 연산으로 속도가 느림, 그래서 하이브리드(비대칭+대칭) 방식 사용**. 몰라서 답 못함.
18. **정답 그대로**. 인증된 세션(쿠키 등) 탈취.
19. **정답 그대로**. 규칙 기반 트래픽 허용/차단.
20. **정답: 봇넷(분산된 다수 좀비PC)으로 대량 트래픽을 동시 전송해 서비스거부 유발**. "감염된 리소스"까지만 답하고 "분산+대량+서비스거부" 요소가 빠짐.

### 신기술단답(D-12)
1. **정답: 도착순 처리, 단점은 호위효과(Convoy Effect)로 평균대기시간 증가**. 단점 용어가 부정확("최빈값" 등).
2. **정답: 동일 시간할당량을 순서대로 선점 방식으로 부여**. "실행시간 고려해서 분배"는 SJF와 혼동.
3. **정답: 페이징=고정크기+내부단편화, 세그멘테이션=가변크기+외부단편화**. 정확한 용어(내부/외부단편화) 없이 답함.
4. **정답: 라우팅/IP 주소 지정**. "전송"이라고 답해 4계층(전송계층)과 혼동.
5. **정답: TCP=연결지향+신뢰성보장, UDP=비연결지향+빠름(오버헤드 적음)**. "홉 수" 이유는 틀림.
6. **정답 그대로**. 관리 범위: IaaS<PaaS<SaaS 순.
7. **정답 그대로**. VM=게스트OS 통째로, 컨테이너=커널 공유.
8. **정답: Volume/Velocity/Variety**. 몰라서 답 못함.
9. **정답: 블록을 해시로 체인처럼 연결+분산 노드가 함께 검증·저장**. 몰라서 답 못함.
10. **정답: 물리 메모리보다 큰 프로그램 실행 + 멀티프로그래밍 가능**. "DB I/O 속도"로 답해 완전히 다른 방향.
11. **정답: 사물 간 자율적 데이터 통신이 핵심 정의**. MQTT(경량 프로토콜)는 결과적 특징이지 정의 자체는 아님.
12. **정답: 낮은 우선순위 프로세스가 계속 실행 기회를 못 얻는 현상, 해결책은 Aging**. "리소스가 논다"로 답해 개념이 반대.
13. **정답: 상호배제/점유와대기/비선점/순환대기**. 몰라서 답 못함.
14. **정답: 프로세스=독립 메모리공간, 스레드=코드/데이터/힙 공유+스택만 개별**. PCB를 스레드 공유 메커니즘으로 잘못 설명.
15. **정답 그대로**. 도메인명→IP 변환.
16. **정답 그대로**. CPU-메모리 속도차 해소, 참조지역성 활용.
17. **정답: 훈련데이터 성능은 좋지만 새 데이터 일반화 성능이 떨어지는 현상**. "범위가 작아짐"으로 답해 부정확.
18. **정답: UI 레벨에서 사람의 반복 업무를 소프트웨어 로봇이 대신 수행**. 몰라서 답 못함.
19. **정답: 데이터 발생 지점 근처에서 처리해 지연시간 단축(클라우드는 중앙집중이라 지연 발생)**. "공유가 어렵다"는 틀림.
20. **정답: HTTPS=SSL/TLS로 암호화+인증서로 서버 신원확인**. "인가된 네트워크만 접근 허용"은 VPN/방화벽 개념과 혼동.

### 패키징/테스트(D-11)
1. **정답 그대로**. 버전정보/신규기능/개선사항/버그픽스/알려진이슈.
2. **정답 그대로**. 저작권 보호, 허가된 사용자만 이용.
3. **정답: 입력값/실행조건/예상결과(+식별자)**. "누가"는 표준 구성요소가 아님.
4. **정답: 통합테스트는 여러 모듈 결합 시 인터페이스/상호작용 검증**. "더 큰 단위"로만 답해 구체성 부족.
5. **정답: 변경 후 기존 기능이 안 망가졌는지 재확인**. 몰라서 답 못함.
6. **정답 그대로**. 사용자(고객) 관점.
7. **정답 그대로**. Major.Minor.Patch.
8. **정답 그대로**. 스텁=하위모듈 대체+하향식, 드라이버=상위모듈 대체+상향식.
9. **정답 그대로**. 예상 결과 판단 근거.
10. **정답: 등록→담당자할당→원인분석·수정→재테스트→종료**. "배포"는 결함관리 프로세스 자체가 아니며 "담당자 할당" 단계 누락.
11. **정답: 기능성/신뢰성/사용성/효율성/유지보수성/이식성**. 몰라서 답 못함.
12. **정답 그대로**. 통합된 전체 시스템이 요구사항(기능+비기능) 충족 검증.
13. **정답: 새 빌드의 핵심 기능이 최소한 동작하는지 빠르게 확인하는 사전 관문**. "일부러 오류 발생시켜 확인"은 장애주입테스트와 혼동.
14. **정답: 공식 승인되어 이후 변경 통제의 기준이 되는 형상 항목 버전**. git 브랜치 개념으로 답해 부정확.
15. **정답 그대로**. 설치매뉴얼=환경구성, 사용자매뉴얼=기능사용법.
16. **정답: 조건 조합별 결과를 표로 정리해 조합 누락 없이 테스트케이스 도출**. 몰라서 답 못함.
17. **정답: 소스코드+요구사항명세서+설계문서+테스트문서+매뉴얼 등 산출물 전체**. 몰라서 답 못함.
18. **정답 그대로**. 모든 실행 가능 라인이 1회 이상 실행됐는지.
19. **정답: 입력조건의 경계(최솟값/최댓값 부근)에서 오류확률이 높다는 점에 착안한 블랙박스 기법**. 시간 관계상 답변 없이 정답만 제공.
20. **정답: 모든 조건문의 참/거짓 분기가 각각 1회 이상 실행됐는지(구문 커버리지보다 엄격)**. 시간 관계상 답변 없이 정답만 제공.

## 4. 반복 오답 패턴 (D-2 최종 암기 시 재확인)

- 비대칭키 암복호화 방향(공개키로 암호화/개인키로 복호화 — 전자서명은 반대 방향)
- CSRF = 쿠키 자동 첨부 악용(캐싱 아님), SameSite로 완화
- SEED/AES는 둘 다 대칭키(비대칭키 아님)
- VPN = 터널링+암호화가 핵심(차단/우회 아님)
- DDoS = 분산+대량트래픽+서비스거부 세 요소 모두 필요
- RR은 "동일 시간할당량 순서대로"(실행시간 고려 아님)
- OSI 3계층(라우팅/IP) vs 4계층(전송, TCP/UDP) — 이름에 낚이지 말 것
- 가상메모리 목적 = 물리메모리보다 큰 프로그램 실행 + 멀티프로그래밍
- 기아현상=낮은 우선순위가 영원히 못 돎, 해결책 Aging / 교착상태 4조건 암기
- 프로세스=독립 메모리공간 vs 스레드=코드/데이터/힙 공유+스택만 개별
- 과적합=훈련성능↑ 새데이터성능↓(일반화 실패) / 엣지컴퓨팅=데이터 근처 처리(지연단축)
- HTTPS=암호화+인증서(신원확인), "접근제한" 개념 아님
- 회귀테스트(사후, 기존기능 재확인) vs 스모크테스트(사전, 핵심기능만 빠르게) — 목적·시점이 다름
- 베이스라인 = 공식 승인된 변경통제 기준점(git 브랜치 개념 아님)
- 결함관리 프로세스에 "담당자 할당" 단계 빠뜨리지 말 것
