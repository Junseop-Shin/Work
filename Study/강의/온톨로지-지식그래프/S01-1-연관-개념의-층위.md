# S01-1 — 연관 개념의 층위: SKOS·OWL · Semantic Web · Schema

> **성격** — S01의 부록. S01 1절이 연관 개념으로 던진 5개(Semantic Web · Knowledge Graph · Schema ·
> Taxonomy · Thesaurus) 중 자료가 실제로 설명하지 않고 넘어간 것들의 자리를 세운다.
> 강의 자료에 없는 내용이며, 대화로 정리했다.

## 왜 이 문서가 필요한가

S01 자료는 용어를 **나열**하고 넘어간다. 그런데 이 용어들은 층위가 다르고, 특히 **Schema는 같은 단어가
네 층위에서 쓰여서** 짚어두지 않으면 이후 회차에서 계속 흔들린다(예: S26 'Schema-grounded KG 구축').

여기서 세운 기준 하나 — **"기계가 추론할 수 있는가"** — 가 뒤 회차에서 반복해서 쓰인다.

## 1. 세 지식 체계의 구분 기준은 관계 개수가 아니다

**강의의 관점** — Taxonomy의 계층적 관계와 Thesaurus의 범위형·연관 관계를 **모두 포함**한 것이 온톨로지다.
구성 요소로 보면 정확하다. 온톨로지는 상위–하위도 표현하고 동의어·관련어도 표현한다.

여기에 한 층이 더 있으면 그림이 닫힌다. **그 관계들에 논리적 의미가 붙어서 기계가 추론할 수 있게 된 것**이
온톨로지다. 관계 종류를 아무리 늘려도 그것만으로는 큰 Thesaurus에 머문다.

표준으로 보면 선이 선명하다.

| | 표준 | 관계 | 기계가 할 수 있는 일 |
|---|---|---|---|
| Taxonomy | (자유 형식) | 상위–하위 1종 | 분류 · 탐색 |
| Thesaurus | **SKOS** | 동의 · 상위 · 하위 · 관련 | 용어 확장 검색 |
| Ontology | **RDFS / OWL** | 임의 관계 + **논리 제약(axiom)** | **추론** |

- `skos:broader`는 **의도적으로 느슨하다.** 기본이 전이적(transitive)이지 않고, 클래스 포함 관계도 아니다.
  "대충 더 넓은 개념" 정도의 뜻만 갖는다. (전이가 필요하면 `skos:broaderTransitive`를 따로 쓴다)
- `rdfs:subClassOf`는 전이적이고, `owl:disjointWith`·cardinality 같은 제약을 걸 수 있고,
  **추론기(reasoner)가 선언하지 않은 트리플을 만들어낸다.**

즉 세 단계의 차이는 관계 개수가 아니라 **"기계가 추론할 수 있는가"**다.
이 기준을 잡아두면 [S01 6절](S01-기본개념과-실사례.md)의 관계 4분면(Inherited · Inverse)이 왜 나온 건지
바로 연결된다 — **직접 저장한 관계와 추론으로 생긴 관계의 구분**이기 때문이다.

### 1.1 각주 — Taxonomy는 실제로는 트리가 아니다

S01 4절의 트리 그림은 교육용 단순화다. 개는 `포유류`이면서 `반려동물`이고, 제조 부품은 `기계 분류`이면서
`구매 분류`에 속한다. **다중 상속이 생기는 순간 트리가 아니라 DAG가 된다.** 실무 분류체계는 대부분 DAG다.

## 2. Semantic Web — 온톨로지가 왜 하필 웹 표준(RDF/OWL)인가

**데이터를 기계도 읽을 수 있는 형식으로 표현해서 웹에 올려놓은 것.** 팀 버너스리가 제안했고,
2001년 *Scientific American*의 「The Semantic Web」(Berners-Lee · Hendler · Lassila)으로 널리 퍼졌다.
W3C가 표준을 맡았다.

한 줄로는 **문서의 웹(Web of Documents) → 데이터의 웹(Web of Data)** 이다.

```
기존 웹        <h1>자동차</h1>
               사람은 "제목"인 줄 알지만, 기계는 "큰 글씨"인 것만 안다

Semantic Web   그 자동차가 무엇이고(타입) 무엇과 어떤 관계인지를
               기계가 읽는 형식으로 함께 올린다
```

**계층 구조(Semantic Web Stack)**

```
URI / IRI     전역 식별자
RDF           트리플 데이터 모델
RDFS / OWL    ← 온톨로지가 사는 층 (의미 · 논리 제약)
SPARQL        조회
```

**[S01 3절](S01-기본개념과-실사례.md)의 온톨로지·지식그래프가 하필 RDF/OWL로 표현되는 이유가 여기 있다.**
온톨로지는 독립된 기술이 아니라 이 스택의 한 층이다. 강의 뒤쪽의 실습(OWL 설계 · RDF 파이프라인)도
전부 이 스택 위에서 돌아간다.

**Linked Data 4원칙** (버너스리, 2006)

1. 사물에 **URI로 이름**을 붙인다
2. **HTTP URI**를 써서 찾아갈 수 있게 한다
3. URI를 조회하면 **표준 형식(RDF · SPARQL)으로 유용한 정보**를 준다
4. 다른 URI로 가는 **링크를 포함**한다

**여기서 URI가 핵심이다.** S01 5.1절의 "같은 의미, 다른 용어" 문제를 웹 규모로 풀려면 전역 식별자가 있어야 한다.
한 조직 안에서는 내부 ID로 되지만, 조직을 넘어 데이터를 합치려면 **누가 발행했는지가 이름에 박혀 있어야** 한다.
UMLS의 개념 고유번호(CUI)나 schema.org 타입이 URI로 발행되는 게 그래서다.

> **현실 메모** — 웹 전체가 기계가 읽는 데이터가 된다는 원래 비전은 실현되지 않았다.
> 실제로 살아남은 건 셋이다 — **schema.org 구조화 데이터**, **Linked Open Data**(DBpedia · Wikidata),
> **엔터프라이즈 지식그래프**. 2012년 구글이 Knowledge Graph를 발표하면서 용어의 무게중심이 옮겨갔고,
> 그래서 "Semantic Web의 실질적 후계자가 Knowledge Graph"라는 서술이 흔하다.
> 강의가 KG를 전면에 두고 Semantic Web을 연관어로만 언급한 배경이기도 하다.
>
> **S02에서 확인됨** — [S02 1.4절](S02-설계-원칙.md)의 시대별 시각 표가 이 경로를 그대로 보여준다.
> 2000s를 "만들기엔 너무 무겁고 비싼 것으로 인식됨", 2012를 "구글이 의미 기반 검색에 적용"으로 적고 있다.

## 3. Schema — 같은 단어, 네 층위

| 이름 | 규정하는 것 | 위반하면 | 세계 가정 |
|---|---|---|---|
| **DB 스키마** (DDL) | 테이블 · 컬럼 · 타입 · FK | **삽입 거부** | 닫힌 세계 (CWA) |
| **JSON Schema** | 문서의 구조 | **검증 실패** | 구조만, 의미 없음 |
| **schema.org** | 웹 콘텐츠용 어휘 (타입·속성 이름) | 아무 일도 안 일어남 (무시) | 느슨 |
| **RDFS / OWL 온톨로지** | 개념의 의미와 논리 관계 | **거부가 아니라 추론이 일어남** | 열린 세계 (OWA) |

**DB 스키마는 제약(constraint)이고, 온톨로지는 의미(semantics)다.** 선언 모양이 비슷해서 제일 헷갈리는 지점이다.

```
DB      age INT NOT NULL
        → 값이 없으면 INSERT 거부                      (검사)

OWL     :hasParent rdfs:domain :Person   선언
        :john :hasParent :mary           트리플 추가
        → john의 타입이 없다고 거부하지 않는다.
          "john은 Person이다"를 추론해서 지식이 늘어난다   (추론)
```

같은 모양의 `domain` 선언이 **닫힌 세계에서는 검사로, 열린 세계에서는 추론으로** 작동한다.
따라서 **OWL로는 데이터 검증을 할 수 없다** — 위반이 오류가 아니라 새로운 사실이 되어버리니까.
검증하려면 별도 언어가 필요하고, 그게 **SHACL**이다.

> OWA/CWA와 SHACL은 실습 회차에서 다시 나온다.
> → [`ontology-pipeline/docs/1.core-concepts.html`](../../../Projects/ontology-pipeline/docs/1.core-concepts.html) (OWA/CWA) ·
> [`4-1.cleaning-mapping-validation.html`](../../../Projects/ontology-pipeline/docs/4-1.cleaning-mapping-validation.html) (SHACL)

**그럼 schema.org는 온톨로지인가** — 온톨로지라기엔 얕고 느슨하다. 타입 계층은 있지만 `domain`/`range`도
강제나 추론이 아니라 "expected type" 힌트에 가깝다. **의도된 설계다.** 웹 규모에서 엄격함은 채택률을 죽인다.
[S01 7절](S01-기본개념과-실사례.md)의 두 사례가 정확히 이 스펙트럼의 양 끝이다.

```
엄격 · 전문가 큐레이션 ─────────────────── 느슨 · 대중 채택
       UMLS                              schema.org
   (127 타입 · 54 관계)              (강제 없음, 틀려도 무시)
```

> **S02·S02-1로 이어짐** — 이 "제약 vs 의미" 축이 [S02-1 2절](S02-1-두-계보와-발견-메커니즘.md)의
> 두 계보 비교에서 그대로 재사용된다. Palantir 계보의 온톨로지는 **제약 쪽**이다.

## 4. 한 장의 지도

```
Semantic Web        비전 · 생태계 — 데이터를 기계가 읽게 웹에 올린다
│
├─ 표현 층          URI → RDF → RDFS/OWL → SPARQL
│                                  ↑ 온톨로지가 사는 층
├─ 구현물           Knowledge Graph  (S01 3절)
│
├─ 지식 체계의 강도  Taxonomy  <  Thesaurus(SKOS)  <  Ontology(OWL)
│                            ↑ 기준은 관계 개수가 아니라 추론 가능성 (1절)
│
└─ 혼동 주의        DB 스키마 · JSON Schema  = 제약/검증. 의미 층이 아니다
                    schema.org               = 웹용 느슨한 어휘
```

## 5. 세 사례가 공통으로 보여주는 것

S01 7절의 WordNet · UMLS · schema.org를 나란히 놓으면 이렇다.

| 사례 | 통일하려는 대상 | 규모 |
|---|---|---|
| WordNet | 일반 영어 어휘의 의미 | synset 단위 |
| UMLS | 의료 도메인의 용어체계 | 60+ 어휘체계 통합 |
| schema.org | 웹 콘텐츠의 의미 표현 | 검색엔진 간 합의 |

셋 다 **"같은 것을 다르게 부르는 문제"**에서 출발했다. S01 5.1절의 첫 번째 실익("같은 의미, 다른 용어")이
온톨로지 구축의 진짜 동기라는 걸 사례가 증명한다. 규모와 도메인은 달라도 해법의 모양은 같다 —
**동의어 묶기 → 종류 부여 → 관계 정의.**

각 사례가 그 해법을 어디에 구현했는지도 다르다.

- **WordNet** — 단위 자체를 synset(동의어 집합)으로 잡아 동의어 묶기를 **데이터 모델에 내장**
- **UMLS** — Metathesaurus(묶기)와 Semantic Network(종류)를 **두 층으로 분리**해 각각 독립적으로 확장
- **schema.org** — 묶기를 포기하고 **공용 타입 이름만 합의**. 채택률을 우선
