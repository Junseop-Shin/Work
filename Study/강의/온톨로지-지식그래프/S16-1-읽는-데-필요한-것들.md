# S16-1 — 읽는 데 필요한 것들

> 성격: 부록. [S16A](S16A-OntoEA-온톨로지를-넣은-엔티티-정렬.md)·[S16B](S16B-BERTMap-문맥-임베딩-기반-정렬.md)

이 회차는 두 논문이 서로 다른 계열의 도구를 쓴다. OntoEA는 [S13](S13-KG-임베딩-기초.md)의

idf)를 가져온다.

이미 다룬 것은 다시 쓰지 않는다. hinge loss는 [S15-1 12절](S15-1-읽는-데-필요한-것들.md),

있다.

## 1. BERT가 Word2Vec과 다른 점

[S15-1 1절](S15-1-읽는-데-필요한-것들.md)의 Word2Vec은 **단어 하나에 벡터 하나**를 준다.
`bank`는 어디에 나오든 같은 벡터다. 강둑이든 은행이든 구분이 없다.

**BERT는 문장을 통째로 읽고 그 자리에서 벡터를 만든다.** 같은 단어라도 앞뒤가 다르면 다른 벡터가
나온다. 이것이 **문맥 임베딩**이라는 말의 뜻이고, S16B 1절 표의 "비문맥 word embedding"과
"문맥 임베딩(BERT)"이 갈리는 지점이다.

온톨로지 정렬에서 이 차이가 왜 중요한가. `muscle layer`와 `muscularis propria`는 글자가 전혀
겹치지 않는다. 표면형만 보는 lexical matching은 물론이고, 단어별 벡터를 평균 내는 방식도
`muscularis`나 `propria` 같은 단어가 학습 corpus에 드물면 힘을 못 쓴다. BERT는 두 표현이 같은
문맥에서 쓰이는 것을 사전학습 단계에서 이미 봤을 수 있다.

## 2. 사전학습과 fine-tuning

BERT를 쓰는 일은 두 단계다.

| | 무엇을 하나 | 누가 하나 |
|---|---|---|
| 사전학습 (pre-training) | 대량의 일반 텍스트로 언어 자체를 익힌다 | 보통 남이 해둔 것을 받아 쓴다 |
| 미세조정 (fine-tuning) | 내 과제의 데이터로 조금 더 학습한다 | 내가 한다 |

**Bio-Clinical BERT**는 의학 논문과 임상 기록으로 사전학습한 BERT다. BERTMap은 이걸 받아서
"이 두 label이 동의어인가"라는 과제로 미세조정한다. 처음부터 학습하지 않으니 GPU 한 장으로
끝난다(S16B 5절).

**BERTMap의 미세조정 과제는 이진 분류다.** 두 label을 입력으로 넣고 동의어면 1, 아니면 0을
맞히게 한다. 출력이 `(1 − s, s)` 두 숫자인 것이 이 뜻이고, `s`가 동의어 쪽 확률이다.

## 3. positive와 negative, 그리고 hard negative

분류 모델을 학습하려면 맞는 예와 틀린 예가 둘 다 필요하다.

- **positive**는 실제로 동의어인 label 쌍이다. 같은 class에 붙은 두 label을 쓰면 공짜로 얻는다
- **negative**는 동의어가 아닌 쌍이다. 아무 class나 둘 골라 label을 뽑으면 된다

문제는 **아무렇게나 뽑은 negative가 너무 쉽다**는 것이다. `공기압축기`와 `대퇴골`을 놓고
"동의어인가" 물으면 모델은 글자만 봐도 아니라고 답한다. 이런 쉬운 예만 잔뜩 주면 모델은 어려운
경계를 배우지 못한다.

**hard negative는 헷갈리게 비슷하지만 정답은 아닌 예다.** BERTMap은 이걸 sibling class에서
뽑는다. 같은 부모 밑의 형제 class는 서로 비슷한 자리에 있으면서 서로 다른 개념이다.

```
Vehicle
├── ElectricBus     ← 이 둘의 label 쌍이 hard negative
└── GasolineBus
```

> **여기 가정이 하나 들어간다.** 형제 class는 서로 배타적이라는 것이다. 온톨로지에
> `owl:disjointWith`가 선언돼 있으면 확실하지만, 선언이 없는 경우가 많아 **선언 없이도 형제면
> disjoint로 친다.** 슬라이드가 "거친 가정"이라고 부르는 것이고, 이 가정이 틀리는 경우와 그
> 대가는 [S16-2 3절](S16-2-정렬이-서는-자리.md)에 적었다.

`identity synonym (ids)`는 자기 자신과 짝지은 쌍(`ω1 = ω2`)이다. 완전히 같은 문자열은 반드시
동의어라는 신호를 강하게 넣는 장치다.

## 4. WordPiece와 sub-word

**BERT는 단어를 그대로 먹지 않고 조각으로 쪼갠다.** 이 쪼개는 방식이 WordPiece다.

```
muscularis  →  muscular ##is
appendix    →  append ##ix
```

**왜 쪼개는가.** 사전에 없는 단어(OOV, out-of-vocabulary)를 만나도 조각으로는 처리할 수 있기
때문이다. 의학 용어나 사내 약어처럼 새로 만들어지는 말이 많은 영역에서 특히 중요하다. 단어
단위로만 다루면 사전에 없는 순간 아무 정보도 못 얻는다.

BERTMap은 이 조각을 후보 검색에도 쓴다(S16B 6절). 두 class 이름이 **조각을 공유하면** 후보로
본다. 글자가 완전히 같지 않아도 걸린다.

## 5. inverted index와 idf

**inverted index는 검색 엔진의 기본 자료구조다.** 보통은 "문서 → 그 안의 단어"로 저장하는데,
이걸 뒤집어 "단어 → 그 단어가 나오는 문서 목록"으로 저장한다. 그래서 뒤집힌(inverted) 색인이다.

BERTMap의 색인은 이렇게 생겼다.

```
"muscular"  →  { Class_A, Class_B, Class_C, ... }
"##is"      →  { Class_A, Class_D, ... 수만 개 }
```

**왜 필요한가.** 두 온톨로지의 모든 class 쌍을 다 비교하면 `O(n²)`이다. 의료 온톨로지는 10만
× 15만 규모라 150억 쌍이 나온다. BERT를 그만큼 호출하는 것은 불가능하다. 색인을 쓰면 **조각을
공유하는 class만 꺼내볼 수 있다.**

**idf는 흔한 조각의 값을 깎는 장치다.**

```
idf(t) = log₁₀ ( |C'| / |I'[t]| )
```

`|C'|`가 전체 class 수, `|I'[t]|`가 조각 `t`를 가진 class 수다. `##is` 같은 조각은 수만 개
class에 들어 있어서 분모가 커지고 `idf`가 0에 가까워진다. 반대로 `muscularis`처럼 몇 개
class에만 있는 조각은 분모가 작아 값이 크다. **드문 조각을 공유하는 쌍일수록 진짜 후보일
가능성이 높다**는 판단을 숫자로 만든 것이다.

이렇게 매긴 점수로 정렬해 상위 `k = 200`개만 남기면 비교 횟수가 `O(kn)`이 된다.

## 6. Precision · Recall · F1

이 회차에서 처음 나오는 지표다. 앞 회차의 MRR·Hits@k와 재는 것이 다르다.

| | 무엇을 재나 | 쓰는 곳 |
|---|---|---|
| MRR · Hits@k | 정답이 후보 목록에서 **몇 번째**에 있나 | OntoEA (순위 매기기) |
| Precision · Recall · F1 | 내놓은 답이 **맞나, 그리고 다 찾았나** | BERTMap (분류) |

**Precision(정밀도)은 내놓은 것 중 맞은 비율이다.** 100개를 정렬됐다고 내놨는데 90개가 맞으면
0.9다. **Recall(재현율)은 실제 정답 중 찾아낸 비율이다.** 정답이 200개인데 90개를 찾았으면
0.45다.

**둘은 맞바꿈 관계다.** 임계값을 높여 확실한 것만 내놓으면 precision이 오르고 recall이 떨어진다.
S16B 10절 표의 `string-match` 행이 정확히 그 모습이다. precision 0.987에 recall 0.194다. 거의
다 맞지만 대부분을 놓친다.

**F1은 둘의 조화평균이다.** 한쪽만 높아서는 값이 오르지 않는다.

```
F1 = 2 · (P · R) / (P + R)
```

`Macro-F1`은 여러 갈래로 나눠 F1을 각각 구한 뒤 평균 낸 것이다.

**이 구분이 S16B 8절을 읽는 열쇠다.** mapping extension은 후보를 넓혀 **recall을 올리고**,
mapping repair는 논리 충돌을 걷어내 **precision을 올린다.** 슬라이드가 "비대칭 역할 분담"이라고
부른 것이 이 두 지표를 각각 담당한다는 뜻이다.

## 7. 지도 · 비지도 · 준지도와 seed mapping

**seed mapping은 미리 사람이 확인해둔 정답 짝이다.** "이 온톨로지의 `Person`은 저 온톨로지의
`Human`과 같다"를 몇 개 손으로 적어주는 것이다.

| | seed를 쓰나 | 이 회차에서 |
|---|---|---|
| 지도 (supervised) | 많이 쓴다 | 해당 없음 |
| 준지도 (semi-supervised) | 조금 쓴다 | OntoEA seed mapping 20%, BERTMap의 `co` corpus |
| 비지도 (unsupervised) | 안 쓴다 | BERTMap의 `io`만 쓰는 설정 |

BERTMap이 비지도로도 돌아가는 이유가 여기 있다. `io` corpus는 **한 온톨로지 안에서** 같은
class에 붙은 label들끼리 짝지은 것이라 사람의 주석이 전혀 필요 없다. S16B 1절의 "지도 데이터가
없는 것이 아니라 온톨로지 구조 안에 이미 라벨이 숨어 있다"가 이 뜻이다.

## 8. Surface Information

슬라이드는 "각 entity의 이름, 설명 등의 텍스트 정보"라고 한 줄로 정의하고 지나간다. 정작
**왜 이걸 떼어내고 실험을 두 번 하는지**가 빠져 있다.

**SI는 그래프 구조가 아닌 것 전부다.** entity의 이름 문자열, 설명문, 속성값 같은 텍스트다.
반대편의 구조 정보는 어떤 entity가 어떤 relation으로 어디에 붙어 있는가다.

**떼어내는 이유는 이름이 너무 많이 알려주기 때문이다.** 영어 위키의 `Victoria`와 프랑스어
위키의 `Victoria`는 문자열이 같다. 이름만 비교해도 상당수가 맞는다. 그러면 모델이 그래프
구조를 배운 것인지 이름을 베낀 것인지 구분할 수 없다. 그래서 Entity Alignment 논문들은
**w/o SI(이름을 가린 설정)를 기본 비교로 두고** w/ SI를 따로 잰다.

[S15-2 3절](S15-2-공리를-어디에-두는가.md)에서 본 것과 같은 구도다. Pre-trained Word2Vec이
HeLis에서 구조 기반 방법을 전부 앞선 것도 이름이 이미 답을 담고 있었기 때문이다. **이름이
얼마나 알려주는가가 계속 문제가 된다.**

**OntoEA가 SI를 쓰는 방식은 단순하다.** 이름의 사전학습 word embedding으로 `h, r, t, c`의
초기값을 잡는다(S16A 15절). 모델 구조는 그대로고 **출발점만 바뀐다.** 무작위에서 시작하는 대신
이름이 비슷한 것끼리 이미 가까운 자리에서 시작한다.

**표를 읽을 때 주의할 것이 있다.** S16A 14절과 15절의 표는 블록이 나뉘어 있고 **비교군도
다르다.**

| | 비교군 |
|---|---|
| w/o SI | MTransE · JAPE · SEA · GCNAlign · BootEA · RSN4EA · AliNet |
| w/ SI | AttrE · MultiKE · RDGCN |

**두 블록을 세로로 이어 비교하면 안 된다.** SI를 쓰는 모델은 애초에 다른 재료를 먹는다. 같은
OntoEA도 EN-FR-V1 H@1이 w/o SI에서 .566, w/ SI에서 .797인데, 이건 모델이 좋아진 것이 아니라
재료가 늘어난 것이다. 어느 쪽이 자기 과제에 맞는 숫자인지는 **내 데이터에 쓸 만한 이름이
있는가**로 정해진다.

**SI가 항상 도움이 되지도 않는다.** D-W는 SI를 넣으면 전반 성능이 떨어진다(S16A 15절).
슬라이드는 그 사실만 적고 이유는 말하지 않는다. 해석은
[S16-2 4절](S16-2-정렬이-서는-자리.md)에 적었다.

## 9. limit-based scoring loss

OntoEA의 세 loss(`L_E`, `L_O`, `L_M`)가 전부 같은 꼴이다.

```
[γ¹ + f(positive) − f(negative)]₊  +  α·[f(positive) − γ²]₊
     ── 앞항: margin loss ──            ── 뒷항: limit-based ──
```

`[...]₊`는 `max(0, ...)`이고 [S15-1 12절](S15-1-읽는-데-필요한-것들.md)의 hinge loss와 같다.

**앞항은 정답이 오답보다 `γ¹`만큼 더 좋으면 만족한다.** 상대 비교만 한다. 그래서 정답 점수와
오답 점수가 둘 다 나빠도 격차만 벌어져 있으면 벌점이 0이 된다.

**뒷항이 그 구멍을 막는다.** 정답의 점수 자체가 `γ²` 아래로 내려가야 만족한다. 슬라이드가
"positive 점수 자체를 낮춤"이라고 적은 것이 이것이다.

> `f`는 거리이므로 **작을수록 좋다.** `f(positive)`가 작아야 한다는 뜻이다.

## 10. locality principle

S16B 8절의 mapping extension이 기대는 원리다. **두 class가 같은 것으로 판정됐다면, 그 부모끼리와
자식끼리도 같을 가능성이 높다**는 것이다.

```
Sup(c)  ↔  Sup(c')     ← 새 후보
  c     ↔    c'        ← 이미 확정된 anchor mapping
Sub(c)  ↔  Sub(c')     ← 새 후보
```

확정된 mapping 하나를 발판 삼아 위아래를 훑고, 거기서 새로 확정되면 다시 그 주변을 훑는다.
새 mapping이 안 나올 때까지 반복한다. **온톨로지가 계층이라는 사실을 검색 순서에 쓰는 것**이고,
BERT를 부르는 횟수를 줄이는 효과도 같이 얻는다.

| 사전학습 · fine-tuning | 남이 익힌 모델을 받아 내 과제로 조금 더 학습 | 2절 | S16B 5절 |
