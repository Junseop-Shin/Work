## 1. 용어 정리

| 용어 | 정의 |
|---|---|
| **Ontology** | 특정 도메인의 지식을 **공유·재사용**할 수 있도록 개념(concepts)과 그 관계(relations)를 **명시적·형식적으로 정의한 명세서** |
| **Ontology Learning (OL)** | 다양한 형태의 데이터로부터 **인간 개입을 최소화하여** 온톨로지를 **반자동·자동으로** 구축·확장하는 프로세스. 웹의 **구문적 상호운용성 → 의미적 상호운용성**으로 확장 |
| **Taxonomy** | 도메인 내의 개념들을 **계층적 구조로 분류한 체계**. 논문 1에서는 방대한 OL method들을 **입력 데이터 형식**과 **사용 기술**로 분류하는 첫 knowledge engineering 단계로 활용 |

## 2. Ontology Learning — 왜 등장했나

- 최근 데이터의 폭발적 증가와 다양한 형태(구조화 · 반구조화 · 비구조화)의 데이터로 인해,
  **반자동·자동으로 온톨로지를 구축·확장하는 Ontology Learning** 기술이 대안으로 부상
- 데이터로부터 **인간의 개입을 최소화**하면서 온톨로지의 구성 요소인 **개념(Concepts) · 관계(Relations) · 공리(Axioms)**를
  추출·생성하는 것을 목적으로 함
- 수동 구축에서 발생하는 **지식 습득의 병목 현상**을 ML·NLP로 대규모 데이터에서 자동 습득함으로써 극복

**Two Approaches**

| 접근 | 초점 |
|---|---|
| 지식 엔지니어 **지원 도구** 개발 | 온톨로지 설계자가 효율적으로 구축할 수 있도록 돕는 **도구 개발** |
| **자동/반자동 구축** | 다양한 데이터 소스에서 온톨로지 요소를 **반자동·자동으로 도출** |

## 3. 논문 ①의 출발점 — Limitations

**전통적으로 온톨로지는 전문가가 수동으로 설계·구축했다.** 고비용·저효율이며 전문가 주관에 따른 편향·오류가 발생한다.

| | 한계 | 내용 |
|---|---|---|
| ① | **방법론의 파편화** | 지난 **25년간** 수많은 OL 접근법이 제안되었으나 방법론이 너무 다양함. 각기 다른 **데이터 소스**(텍스트 · 사전 · 지식베이스)와 **기술**(통계 · 언어학 · 논리)을 사용하고 있어 **최적의 방법을 선택하기 어려움** |
| ② | **지식 체계화의 부재** | OL 방법론들을 관통하는 **종합적인 분류 체계(taxonomy)가 부족**. 관련 연구들이 어떻게 연결되고 어떤 장단점이 있는지 전체적인 **landscape가 불분명** |

→ **논문 ①의 출발점: 위 문제들을 풀기 위해 OL 방법을 taxonomy로 체계화**

## 4. 두 개의 분류 축

### 4.1 구축의 계층적 구조 — Layer Cake ('무엇을 뽑는가')

- 온톨로지 학습은 **한 번에 완료되는 것이 아님**
- 용어 추출(Term extraction) → 동의어(Synonyms) 식별 → 개념(Concepts) 형성 →
  계층 관계(Concept Hierarchies, Taxonomy) 구축 → 비계층적 관계(Relations) 식별 → 규칙(Rules) 정의
  로 **점진적인 구조**를 따름

```
        ┌──────────────┐
        │    Rules     │   ← 최상단까지 가는 도구는 드묾
      ┌─┴──────────────┴─┐
      │    Relations     │   계층이 아닌 비계층 '관계'
    ┌─┴──────────────────┴─┐
    │ Concept Hierarchies  │   is-a 분류 골격을 이룸
  ┌─┴──────────────────────┴─┐
  │        Concepts          │
┌─┴──────────────────────────┴─┐
│         Synonyms             │
├──────────────────────────────┤
│          Terms               │   아래층일수록 기초적
└──────────────────────────────┘
                 위로 갈수록 추상적 · 어려움
```

- **최상단 Rules까지 가는 도구는 드묾**
- **도구가 이 케이크의 '어디까지 뽑는지'가 곧 비교 기준이 된다**

### 4.2 Wong's 기술 3분류 ('어떻게 뽑는가')

| 분류 | 기법 | 접근 방식 |
|---|---|---|
| ① **통계 기반** (Statistics-based) | 군집화(Clustering), 잠재 의미 분석(LSA), 연관 규칙 마이닝 등 | **데이터의 분포나 유사성**으로부터 지식을 발견 |
| ② **언어 기반** (Linguistics-based) | 품사 태깅(POS Tagging), 구문 분석, 어휘·구문 패턴(Lexico-syntactic patterns) 분석 등 | 텍스트 데이터의 **언어적 구조**에서 용어와 관계를 추출 |
| ③ **논리 기반** (Logic-Based) | 유도 논리 프로그래밍(ILP), 논리적 추론 | 온톨로지의 **공리(axioms)**나 복잡한 관계를 모델링 |

원 논문의 기법 목록:

| Main group | Used techniques |
|---|---|
| **Statistics-Based** | Clustering · Latent semantic analysis · co-occurrence analysis (dependency measures, similarity measures) · Term subsumption · contrastive analysis · association rule mining |
| **Linguistics-Based** | part-of-speech tagging · sentence parsing · syntactic structure analysis · dependency analysis · semantic lexicon · lexico-syntactic patterns · semantic templates · subcategorization frames · seed words |
| **Logic-Based** | inductive logic programming · logical inference |

> [S03A 4절](S03A-용어-추출-P-Mod.md)의 "① 언어적 후보 추출 → ② 통계적 선별" 2단 구조가
> Wong 분류의 ②와 ①을 순서대로 쓴 것이었다. **③ 논리 기반은 앞의 두 논문에 없다.**

# 논문 ① — OL 방법론을 온톨로지로 체계화

## 5. 지식 공학(Knowledge Engineering) 접근

- OL 방법론들을 **나열하는 것을 넘어**, **방법론 자체를 체계적으로 조직하고 관리**하는 구조적 접근
- 파편화된 OL 기법을 효율적으로 **탐색·재사용**하기 위해, **OL이라는 도메인 지식 자체를 온톨로지로 모델링**

**계층 구조** — 학습 기법들의 특징을 하나의 체계적인 틀(taxonomy) 안에 담아서 관리

| 단계 | 내용 |
|---|---|
| ① **핵심 기준(Criteria) 정의** | OL 방법을 `Used techniques` · `Authors` 두 축으로 분류할 기준 설정 |
| ② **방법론 범주화(Name_of_method)** | 입력 형식 · 태스크별 **10개 범주**로 계층 분류. Protégé로 온톨로지 모델의 **기초 데이터** 구축 |
| ③ **속성 매핑** | 각 범주에 실제 사용하는 기법 및 연구자를 **속성으로 연결** |

⇒ 사용자가 **목적(= 입력 데이터 형식 등)에 맞는 최적의 학습 기법을 쉽게 선택·적용**할 수 있도록 가이드라인 제공

## 6. 1단계 — 핵심 기준 정의

- 온톨로지를 체계화하기 위한 **가장 상위의 분류 기준(Criteria)**을 정의하는 단계
- 본 논문에서는 OL 방법론을 분류하기 위해 **`Used techniques`(사용된 기술)**와 **`Authors`(저자)** 두 가지를 기준으로 삼음
- **Ontology 설계의 척추 역할**

```
owl:Thing ──▷ Methods  ──▷ Name_of_method
          ──▷ Criteria ──▷ Authors
                       ──▷ Used_techniques
```

## 7. 2단계 — 방법론 범주화

- 온톨로지 학습의 구체적인 방법론들을 포함하는 **`Methods` 클래스**와 그 **하위 클래스(`Name of method`)**를 정의
- **입력 데이터 형식** 및 **태스크·표현 형식**에 따라 **10개 범주**로 구분

| 기준 | 범주 |
|---|---|
| **입력 기준** | 사전 / 텍스트 / 지식 베이스 / 반구조화 스키마 / 관계형 스키마 |
| **태스크·표현 기준** | 용어 추출·개념 형성 / 관계 발견 / 소셜 데이터·교차 언어 / Linked Data 마이닝 / DL·OWL 개념 학습 |

- 10개 범주 아래에, 각 방법을 특징짓는 **2개 핵심 속성** 부여
  - **Used Techniques**: 통계 기반 · 언어 기반 · 논리 기반 등 사용된 **주요 알고리즘이나 접근법**에 따라 세분화
  - **Authors**: 그 방법을 제안한 **연구자**를 매핑

## 8. 3단계 — 세부 속성 및 관계 매핑

- **특정 학습 방법**을 선택하여 그에 연결된 기법과 저자 정보를 세부적으로 **연결(매핑)**하는 단계
- ex. 텍스트 범주 아래에 **실제 기법**(topic signature, clustering, FCA 등)과
  **연구자**(Hearst, Kietz, Nobécourt …)가 **속성/인스턴스로 연결**
- 즉, **온톨로지를 온톨로지로 모델링한 구조**

이를 통해 시스템은 **"어떤 기술을 사용하여 어떤 저자가 온톨로지를 구축했는가?"**라는 질문에
**추론을 통해** 답할 수 있게 된다.

## 9. 역량 질문(Competence Questions)과 검증

- 온톨로지가 특정 도메인의 지식을 **얼마나 잘 담고 있는지**, 혹은 사용자의 질의에 **얼마나 정확하게 답변할 수 있는지**
  측정하기 위한 **질문 세트**
- 온톨로지 공학에서 통용되는 정의상, 온톨로지가 답할 수 있어야 하는 질문을 **미리** 정의함
  - 구축 **전에** "이런 질문에 답해야 한다"를 정하고, 구축 **후에 실제로 이에 답하는지** 확인
  - **다만, 본 논문에서는 구축된 온톨로지의 정확성을 사후 검증하는 용도로 사용하였음**

**검증 절차**

- 구축된 온톨로지에서 정보를 추출하기 위해 **질의 알고리즘**을 사용
- 질문을 **기술 논리(Description Logic) 질의**로 구현하여, 시스템이 **논리적 추론을 통해 정확한 결과를 도출하는지** 테스트

### 실험적 사례

```
질의:  통계적 접근(Statistical approach) · 매핑(Mapping) · 자연어 처리(NLP) 기법을 사용하는
       온톨로지 학습 방법 중 특정 저자(ex. Bachimont)의 방법론을 찾아라

DL query:
  Methods
    and (hasCriterion some Statistical_approach)
    and (hasCriterion some Mapping_techniques)
    and (hasCriterion some NLP_techniques)
    and (hasCriterion some Bachimont)

결과:  'Methods for ontology learning from texts' 단 1개
```

- **검증**: Protégé 소프트웨어 내에서 필요한 조건을 만족하는지 **추론 과정을 거쳐** 최종 결과값이 도출되는지 확인
- ⇒ 단순히 지식을 분류하는 것에서 나아가, 구축된 온톨로지가 **실무적인 정보 탐색이나 지식 관리에 활용 가능한 수준인지** 확인

## 10. 논문 ① — Contributions & Future Works

**Contributions**

- OL 방법론들을 **체계화**하고, 이를 **온톨로지 형태로 모델링**하여 **실용적인 가이드라인** 제공
- 구축된 온톨로지가 올바른지 확인하기 위해 **역량 질문(Competence Questions)**을 설계하였으며,
  **Description Logic을 활용한 질의**로 특정 요구 사항에 맞는 학습 방법을 도출할 수 있음을 검증

**Future Works**

| | 내용 |
|---|---|
| **웹 데이터 활용** | 대규모 웹 데이터에서 발생하는 **노이즈 · 권위성 · 타당성** 문제를 해결해야 함 |
| **사회적 데이터 통합** | 사용자 참여형 데이터를 구축 과정에 반영하여 **지식의 합의(consensus)**를 도출하는 것이 중요 |
| **복잡한 온톨로지로의 확장** | 현재의 **경량 온톨로지(lightweight)**를 넘어, **공리(axioms) 학습** 기술을 고도화하여 **중량급 온톨로지(heavyweight)**로 발전 |
| **재사용성** | **전이 학습(Transfer Learning)** 및 기존 온톨로지의 **부분적 재사용**을 통해 새로운 도메인으로의 적용을 가속화 |

# 논문 ② — 텍스트 기반 OL 도구 21개의 지식 저장소

## 11. 왜 텍스트인가

- 웹 정보의 대부분은 텍스트 형태이나, 데이터가 **비정형·파편화**되어 있어 컴퓨터가 이를 의미 있게 처리하기 어려움
- 따라서 다양한 **Ontology Learning Tools**를 효과적으로 활용하여 구축 과정을 **자동화·반자동화**하는 기술이
  현대 정보 시스템의 **상호운용성**을 높이기 위해 매우 중요해졌음

**Ontology Learning from Texts**

- 온톨로지는 **지식의 개념과 관계를 구조화한 모델**
- 사람이 수작업으로 만드는 것은 비효율적이기에, **텍스트 데이터로부터 자동 생성**하려는 노력이 활발
- NLP · ML · 텍스트 마이닝 기법으로 텍스트 속에 숨겨진 **개념(Concepts) · 관계(Relations) · 공리(Axioms)**를 찾아내고자 함

## 12. 기존 OL 기법의 문제 5가지

| | 문제 | 내용 |
|---|---|---|
| ① | **데이터 다양성과 다국어 문제** | 웹 상의 데이터는 매우 방대하고 형식이 다양하며 다국어로 작성돼 있음. 이 데이터의 **'소음(Noise)'과 방대한 규모에 대응하는 기법이 여전히 부족** |
| ② | **완전 자동화의 불가능성** | 현재의 OL 기술로는 **개념 간의 의미적 일치**를 도출하거나 **고도의 추상화**가 필요한 영역에서 **인간의 인지적 처리와 전문가의 개입이 필수적** |
| ③ | **비분류 관계 추출의 어려움** | 기존 연구들은 상위/하위를 구분하는 **분류(taxonomic) 관계**에 집중해왔음. 복잡하고 세밀한 **'비분류' 관계 추출 기술은 여전히 부족** |
| ④ | **품질 평가 플랫폼의 부재** | 구축된 온톨로지가 얼마나 **올바른지 · 일관성 있는지 · 완전한지**를 **표준화하여 평가할 공통 플랫폼이 부족** |
| ⑤ | **확장성 및 효율성 문제** | 방대한 비정형 데이터 처리를 위해 훨씬 확장 가능하고 효율적인 알고리즘 필요. **분산 컴퓨팅 · Incremental learning · 샘플링 · 모듈화** 기법 등이 개발되고 있음 |

> ③은 [S03B](S03B-비분류-관계-학습.md) 논문이 정면으로 다룬 문제이고,
> ④는 [S03B 6.1절](S03B-비분류-관계-학습.md)에서 "비분류 관계는 정답지가 없다"로 나타난 문제다.
> 서베이가 짚은 5대 문제 중 둘을 앞 회차 논문들이 각각 붙잡고 있었던 셈이다.

## 14. Knowledge Repository Construction — 8개 기준

**기법 분류만으로는 도구 선택이 어렵다.**

저자는 기존의 파편화된 도구들을 통합하여 사용자가 자신의 **목적에 맞는 최적의 도구**를 선택할 수 있도록
**8개 기준**으로 도구를 평가·정리한 **지식 저장소(Knowledge Repository)** 프레임워크를 제안한다.

| # | 기준 | 의미 |
|---|---|---|
| 1 | **도구의 목표 및 범위** (Goal and Scope) | 도구가 궁극적으로 달성하고자 하는 목적 |
| 2 | **적용된 학습 기법** (Learning Technique) | 데이터를 처리하는 구체적인 기술적 수단 |
| 3 | **학습 방법론** (Method Followed) | 특정 학습 기법을 어떤 체계나 절차를 통해 실행하는지 |
| 4 | **사용자 및 전문가 개입** (User and Expert Intervention) | **시스템의 자동화 수준을 판단하는 척도** |
| 5 | **데이터 소스 유형** (Types of Sources) | 지식 추출을 위해 참조하는 입력 데이터의 종류 |
| 6 | **상호운용성** (Interoperability) | 해당 도구가 외부 도구 또는 플랫폼과 결합될 수 있는지 여부 |
| 7 | **평가 지표** (Evaluation Metrics) | 도구가 생성한 결과물이 얼마나 정확한지 측정 |
| 8 | **결과물** (Output) | 학습 도구를 거친 최종 생산물의 형태 |

- 각 기준들은 **57개의 하위 지표**로 세분화 가능
- 사용자는 자신의 환경에 맞춰 **가장 적합한 도구를 필터링**할 수 있게 됨

## 15. Formalization of Knowledge Repository — 집합론

**비정형적이었던 도구 간 비교 데이터를 컴퓨터가 논리적으로 추론할 수 있는 형태의 지식 저장소로 변환한다.**
방대한 정보를 체계적으로 관리하고 효과적으로 검색할 수 있도록 **집합론(Set Theory)을 활용한 수학적 모델**을 구축했다.

**관계 · 정의역 · 치역**

```
R           온톨로지 학습 도구 집합(Ol)과 특성 집합(F) 사이의 관계
            = 도구와 그 도구가 가진 특정 기능을 연결하는 순서쌍 (ol, f)들의 집합

Dom(R) = {ol ∈ Ol : (ol, f) ∈ R for some f ∈ F}
            적어도 하나의 특성 f와 연결된(= 해당 기능을 가진) 모든 도구의 집합

Ran(R) = {f ∈ F : (ol, f) ∈ R for some ol ∈ Ol}
            지식 저장소 내의 도구들에 의해 실제로 구현되거나 지원되는 모든 특성의 집합
```

**Cartesian Product를 통한 공간 구축**

```
Ol × F = {(ol, f) : ol ∈ Ol, f ∈ F}
         모든 도구와 특성의 가능한 모든 조합 → 전체 표본 공간
```

**특성 집합 F**

- **8가지 핵심 분석 기준**을 집합 F의 원소로 확정 — `Lt`(학습기법) · `Ts`(데이터소스) · `Ue`(인적개입) · …
- 각 원소는 다시 **하위 기준(sub-criteria)**으로 세분화 가능

**학습 도구 리스트 Ol**

```
Ol = {Ol₁, Ol₂, …, Ol₂₁}
Ol₁ : ASIUM      Ol₂ : Caméléon      Ol₂₁ : TermExtractor
```

**전체 표본 공간(Ol × F)을 먼저 정의하고 실제 관계 R을 그 부분집합으로 두는 구조다.**
그래서 `Ran(R)`이 "실제로 지원되는 특성"이 되고, 표본 공간과의 차이가 곧 **아무 도구도 제공하지 않는 특성**이 된다.

## 16. Intelligent & Interoperable Expression — OWL 구현

**구현 도구/표준**

- 앞서 정의한 집합들(R, F, Ol)을 **실제 온톨로지로 구현**
- 언어: **OWL**(Ontology Web Language) / 도구: **Protégé**

**모델 구조**

| | 정의 | 이 논문에서 |
|---|---|---|
| **TBox** (Terminological Box) | 개념 클래스와 그들 사이의 관계를 정의하는 **용어 상자** | **92개 클래스**와 **2개 객체 속성**(Object property) 등으로 구성된 전체 온톨로지 구조 |
| **ABox** (Assertional Box) | TBox에서 정의한 클래스들의 실제 **사례(instance)** | 개별 온톨로지 학습 도구들과 그들의 속성값을 담고 있는 **단언 상자** |

**Why Ontology?**

- **단순 표는 검색만 가능한 반면**, 온톨로지는 **명시적으로 입력되지 않은 정보라도** 기존에 저장된
  데이터 간의 관계를 통해 복잡한 맥락을 **자동으로 유추**할 수 있음
- 사용자 질의에 대해 **복합적인 조건을 필터링·매칭**할 수 있음

> **이 절이 [S01-1 3절](S01-1-연관-개념의-층위.md)의 "DB 스키마는 제약, 온톨로지는 의미"를 그대로 되풀이한다.**
> "단순 표는 검색만, 온톨로지는 유추" — 값이 추론에서 나온다는 얘기다.

## 17. Competency Question 기반 추론 메커니즘

- 구축된 **지식 저장소의 유효성을 검증**하고, 사용자가 원하는 최적의 도구를 **지능적으로 찾아내기** 위해
  **CQ 기반 추론 메커니즘**을 설계
  - 온톨로지가 **답해야 할 질문을 정하고 실제로 답하는지 확인** → 답하면 제대로 구축된 것
  - 저장된 정보가 **논리적으로 타당한지** 확인하고, 모델의 **완성도·일관성을 논리적으로 검증**

**동작 방식** — 사용자가 F(핵심 분석 기준)의 원소에 값을 지정한다.

```
ex.  Lt(학습기법) = 통계,  Ts(데이터소스) = 텍스트,
     Ml(방법론) = own method,  Ue(인적개입) = 전문가   인 도구는?
```

- Protégé와 같은 도구에서 제공하는 **추론기(Reasoner, ex. HermiT)**를 활용
  - `Ol`(온톨로지 학습 도구) 중 **조건을 만족하는 부분집합**을 HermiT reasoner가 **추론**
- 이미 수집된 정보를 바탕으로 복잡한 문맥이나 **사용자가 미처 생각하지 못한 기술적 관계까지 자동으로 추론**
- **자연어에 가까운 개념 수준으로 질문을 구성할 수 있음** (단, **실행은 DL 질의로 수동 구현**)

### 검증 결과

| | 질의 | 결과 |
|---|---|---|
| **C1** | 4조건 — '통계적 기법을 사용하고, 텍스트 소스를 기반으로 하며, 자체 방법론을 따르며, 전문가 개입이 필요한 도구는?' | **OntoGain · SubWordNet** 2개로 좁혀짐 |
| **C2** | 조건 집합을 바꿈 | 결과가 **6개로 확장** — TextStorm and Clouds · OntoLearn Tool · Text-To-Onto · ASIUM · OntoGain · SYNDIKATE·CRCTOL |

- **조건에 따라 답 집합이 달라짐**
- **repository가 질의에 정확히 응답 = 검증 성공**

> C2 결과 그림에는 항목이 7개로 보이는데 본문은 6개라고 적혀 있다.
> 13절 도구 표에서 `SYNDIKATE·CRCTOL`이 한 항목으로 묶여 있으므로 그 둘을 하나로 세면 6개가 맞다.

## 18. 논문 ② — Contributions

- 저자는 총 **21개의 텍스트 기반 온톨로지 학습 도구**를 선정하고, 이들의 **목표 / 학습 기법 / 데이터 소스 /
  전문가 개입 여부** 등 **세부 기능을 분석**하여 **통합된 지식 저장소**를 만들었음
- **집합론**을 통해 이를 **형식화**하고, **Protégé**를 활용하여 **OWL 기반의 지식 모델을 구축**하고,
  **Competency Question**을 통해 사용자가 요구사항에 적합한 도구를 **검색·검증**하는 메커니즘을 구현
- 이는 온톨로지를 구축하려는 지식 엔지니어와 도메인 전문가들이 겪는 **도구 선택의 어려움을 해소**하며,
  비정형 데이터로부터 **지식을 구조화하는 과정을 자동화**하는 데 큰 기여를 함
