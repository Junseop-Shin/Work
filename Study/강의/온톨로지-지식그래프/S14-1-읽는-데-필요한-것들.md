# 부록 S14-1 — 읽는 데 필요한 것들

> **성격** — 본편([S14A](S14A-R-GCN-관계별-메시지-전달.md) · [S14B](S14B-CompGCN-합성-기반-관계-표현.md))이
> 슬라이드를 그대로 옮긴 문서라, 슬라이드가 설명 없이 쓰는 용어와 식을 여기서 푼다. 강의 밖
> 해석과 인사이트는 [S14-2](S14-2-이웃에서-오는-표현.md)에 따로 있다.

슬라이드는 각 단계를 네 줄씩 요약한다. "cross-entropy loss는 실제 class의 probability가 낮을수록
큰 값을 가진다" 같은 문장이 한 줄로 지나가는데, cross-entropy가 무엇인지는 말하지 않는다.
이 문서가 그 자리를 메운다.

---

## 1. 왜 이런 모델이 필요한가

### CNN이 푼 문제

이미지를 분류한다고 하자. 픽셀을 전부 일렬로 펴서 신경망에 넣으면 두 가지가 망가진다. 파라미터가
터지고, **위치가 바뀌면 못 알아본다.** 고양이가 왼쪽에 있는 사진과 오른쪽에 있는 사진은 픽셀
배열이 전혀 달라서 각각 따로 배워야 한다.

CNN은 작은 필터 하나를 이미지 전체에 훑는다. 파라미터가 줄고, 왼쪽에서 배운 "모서리 찾기"가
오른쪽에서도 그대로 작동한다. 층을 쌓으면 모서리에서 눈·코로, 다시 얼굴로 올라간다.

### GCN이 푸는 문제

그래프에서 노드의 성질을 알고 싶다. 논문의 분야를 맞힌다고 하자. 노드마다 벡터를 따로 학습하면
([S13](S13-KG-임베딩-기초.md)이 그랬다) 그 벡터는 그 노드의 등장 기록에서만 배운다. 인용이 세
번뿐인 논문은 거의 난수로 남고, 그래프가 가진 정보를 쓰지 못한다.

GCN은 노드의 표현을 이웃에서 만든다. 그리고 **모든 노드에 같은 변환을 쓴다.** 노드가 100만 개여도
변환은 하나다.

| | 무엇을 넘어 공유하나 | 깔린 가정 |
|---|---|---|
| CNN | 위치 | 이미지의 어느 자리든 국소 패턴의 의미가 같다 |
| GCN | 노드 | 그래프의 어느 노드든 이웃을 모으는 방식이 같다 |

**GCN이 CNN에서 잃는 것은 순서다.** 이미지는 필터 9칸에 각각 다른 가중치를 줘서 왼쪽 위와
가운데를 구분한다. 그래프는 이웃 셋 중 어느 게 첫 번째인지가 정의되지 않아 순서를 바꿔도 결과가
같아야 한다. 그래서 전부 같은 변환을 거친 뒤 더한다.

그러면 이웃을 구분할 방법이 없어진다. R-GCN은 **순서로는 못 구분해도 관계 타입으로는 구분할 수
있다**고 답한다. 이것이 [S14A 2절](S14A-R-GCN-관계별-메시지-전달.md)의 대비다.

## 2. 행렬 W가 하는 일

벡터에 행렬을 곱하는 것은 벡터를 다른 벡터로 옮기는 일이다.

```
h = [1, 2]

W = [[1, 0], [0, 1]]      →  [1, 2]      그대로
W = [[0, 1], [1, 0]]      →  [2, 1]      두 성분을 뒤바꾼다
W = [[2, 0], [0, 0.5]]    →  [2, 1]      첫 성분은 2배, 둘째는 절반
```

늘이고 줄이고 섞는다. 차원도 바꿀 수 있다. 100차원 벡터에 50×100 행렬을 곱하면 50차원이 나온다.
layer마다 차원이 달라지는 것이 이 때문이다.

**W 안의 숫자가 학습 대상이다.** 처음엔 난수이고 손실을 줄이는 방향으로 조금씩 고쳐진다. S13에서
엔티티 벡터를 밀었던 것과 같은 일이 여기서는 행렬에 일어난다.

그래서 "relation의 의미를 W_r이 담는다"는 말이 [S14A 6절](S14A-R-GCN-관계별-메시지-전달.md)의
예시가 된다. 같은 이웃 벡터 [1,2]가 `W_소속`을 통과하면 [1,2]이고 `W_저자`를 통과하면 [2,1]이다.

## 3. σ가 없으면 층을 쌓을 수 없다

행렬 곱만 반복하면 층이 합쳐진다.

```
W₂(W₁h) = (W₂W₁)h = Wh
```

100층을 쌓아도 1층짜리와 표현력이 같다. σ(ReLU 등)를 사이에 끼우면 비선형이라 합쳐지지 않는다.

**그렇다고 무한정 쌓을 수도 없다.** 층이 깊어지면 모든 노드의 표현이 서로 비슷해진다. 이웃의
이웃의 이웃까지 모으면 결국 그래프 전체를 평균 내는 셈이 되기 때문이다. 그래서 GNN은 보통 2~3층에
머문다. CNN이 수십 층을 쌓는 것과 결정적으로 다르다.

## 4. h^(l)과 h^(0)

위첨자는 몇 번째 층인지를 가리킨다.

```
h^(0)   입력. 시작 벡터
h^(1)   1홉 이웃을 모은 결과
h^(2)   2홉까지 모은 결과
h^(L)   마지막 층의 출력
```

[S14A 14절](S14A-R-GCN-관계별-메시지-전달.md)의 `e_i = h_i^(L)`가 "마지막 층의 출력을 entity
embedding으로 쓴다"는 뜻이다.

`h^(0)`을 무엇으로 줄지는 선택이다. [S14A 11절](S14A-R-GCN-관계별-메시지-전달.md)의 "feature 또는
학습 가능한 초기 vector"가 그것이고, 이 선택이 새 노드를 다룰 수 있는지를 가른다.

```
① 노드에 feature 가 있으면 그걸 쓴다
   설비 → [타입=가공기, 도입년도=2019, ...]

② 없으면 노드마다 벡터를 하나씩 두고 그것도 학습한다
   설비 E-3 → [0.31, -0.77, ...]     ← S13 의 임베딩 표와 똑같다
```

②를 고르면 GNN을 써도 새 노드는 자리가 없다.

## 5. 학습이란 무엇인가

본편 12절부터 "loss", "cross-entropy", "역전파", "parameter를 수정한다"가 설명 없이 나온다.

### 다섯 단계

```
① 예측을 낸다
② 정답과 비교해 손실(loss) 숫자 하나를 만든다
③ 파라미터를 조금 키우면 손실이 오를지 내릴지 계산한다   ← 기울기
④ 손실이 내려가는 방향으로 조금 움직인다
⑤ 반복
```

S13에서 벡터를 "조금씩 민다"고 했던 것이 이것이다. 여기서는 미는 대상이 W_r 안의 숫자들이다.

### softmax

classifier가 뱉는 것은 그냥 실수 몇 개다. `[2.1, 0.5, -0.3]` 같은 값이라 음수도 있고 합이 1도
아니어서 확률로 쓸 수 없다. softmax는 지수를 취해 전부 양수로 만들고 합으로 나눈다.

```
[2.1, 0.5, -0.3]   →   [0.705, 0.153, 0.142]      합이 1
```

[S14A 13절](S14A-R-GCN-관계별-메시지-전달.md)의 Researcher 0.705 / Paper 0.153 / Organization
0.142가 이렇게 나온 값이다.

### cross-entropy loss

`Loss = −log p(정답 class)` 한 줄인데 숫자를 넣어보면 뜻이 보인다.

```
정답이 Researcher 일 때

모델이 0.3 을 줬다    →  loss = −log(0.3)  = 1.20      크다
모델이 0.7 을 줬다    →  loss = −log(0.7)  = 0.36      줄었다
모델이 0.99 를 줬다   →  loss = −log(0.99) = 0.01      거의 0
```

**정답에 준 확률이 낮을수록 손실이 커진다.** 손실을 줄이는 방향으로 밀면 정답 확률이 올라간다.

### 역전파

손실은 맨 끝에서 계산되는데 고쳐야 할 숫자는 앞쪽에도 있다. W_r은 encoder 안에 있다.

```
그래프 → [R-GCN layers] → 벡터 → [classifier] → 확률 → loss
           W_r 들                   W_c                  ↑
             ↑                       ↑                여기서 계산됨
             └───────────────────────┴─── 거꾸로 전달
```

"네가 이 손실에 얼마나 기여했는지"를 뒤에서 앞으로 전달한다. 그래야 W_r도 고칠 수 있다. 본편
12절의 "loss의 원인을 classifier에서 R-GCN layer까지 거꾸로 전달해 parameter를 수정한다"가 이
말이다. [S13-1 3절](S13-1-기호와-좌표-사이.md#3-미분-가능성이-여는-문)에서 말한 "기울기가 흐른다"와
같은 얘기다.

### 두 태스크는 뒤만 다르다

```
공통        그래프 → [R-GCN encoder] → 노드 벡터

11~13절     → [classifier] → softmax → 확률     학습: cross-entropy
14~16절     → [DistMult]   → 점수              학습: positive 높이고 negative 낮추기
```

앞부분이 같고 뒤에 붙는 head와 loss만 다르다. 그리고 14~16절의 학습 방식은 S13의 negative
sampling과 같다. 달라진 것은 벡터가 표에서 나오지 않고 encoder에서 나온다는 점뿐이다.

## 6. 식 읽기

### R-GCN update equation

```
h_i^(l+1) = σ ( Σ_{r∈R} Σ_{j∈N_i^r} (1 / c_i,r) · W_r^(l) · h_j^(l)  +  W_0^(l) · h_i^(l) )
```

```
h_i^(l+1)          다음 층에서 노드 i 의 표현. 이것을 구하는 것이 목표
σ( ... )           비선형 활성함수. 층이 하나로 합쳐지지 않게 한다
Σ_{r∈R}            모든 관계 타입에 대해
Σ_{j∈N_i^r}          그 관계로 이어진 이웃 j 마다
1 / c_i,r              이웃 수로 나눠 크기를 맞춘다 (학습되지 않는 고정 상수)
W_r^(l)                관계 r 전용 변환 행렬 (학습된다)
h_j^(l)                이웃 j 의 이전 층 표현
W_0^(l) · h_i^(l)  여기에 내 이전 층 표현도 더한다 (self-loop)
```

### CompGCN update equation

```
h_v^(k+1) = f ( Σ_{(u,r)∈N(v)} W_λ(r) · φ(h_u, h_r) )
h_r^(k+1) = W_rel^(k) · h_r^(k)
```

```
Σ_{(u,r)∈N(v)}   노드 v 에 붙은 (이웃 u, 관계 r) 쌍마다
φ(h_u, h_r)          이웃 벡터와 관계 벡터를 먼저 하나로 합친다   ← R-GCN 에 없던 단계
W_λ(r)             그 결과에 방향별 행렬을 곱한다. 정방향 / 역방향 / self 세 개뿐
h_r^(k+1)        관계 벡터도 갱신되어 다음 층 합성에 다시 쓰인다
```

두 식을 나란히 놓으면 차이가 한 곳이다.

```
R-GCN      W_r · h_u              relation 은 어느 행렬을 쓸지 고르는 번호
CompGCN    W_λ(r) · φ(h_u, h_r)   relation 도 벡터를 갖고 먼저 합성된다
```

### 파라미터 복잡도 표기

`O(...)`는 "대략 이만큼에 비례해 늘어난다"는 뜻이다. 상수배는 무시하고 무엇에 비례하는지만 본다.

```
K    layer 수
d    벡터 차원
|R|  관계 수
B    basis 개수

R-GCN    O(B·K·d² + B·K·|R|)
CompGCN  O(K·d²   + B·d + B·|R|)
```

읽는 법은 **|R|이 무엇과 곱해져 있는가**다. R-GCN은 `B·K·|R|`이라 layer 수와도 곱해지고,
CompGCN은 `B·|R|`이라 basis 개수와만 곱해진다. 관계가 1,345개일 때 이 차이가 벌어진다.

### 환원 관계 읽기

[S14B 8절](S14B-CompGCN-합성-기반-관계-표현.md)의 Table 2는 φ와 `W_λ(r)` 자리에 무엇을 넣으면
어느 모델이 되는지를 보여준다.

```
φ = h_u (relation 무시)   +   W_λ(r) = W 하나              →  GCN
φ = h_u                   +   W_λ(r) = W_r 관계별          →  R-GCN
φ = h_u                   +   W_λ(r) = W_dir(r) 방향별     →  D-GCN
φ = α_r · h_u             +   W_λ(r) = W 하나              →  W-GCN
```

**"우리가 더 낫다"가 아니라 "기존 모델들이 우리 틀의 특수 사례다"라는 주장이다.** 일반화 주장이라
성능 비교와 성격이 다르다.

그리고 이 표가 드러내는 것이 하나 더 있다. 기존 모델들이 **전부 φ 자리에 `h_u`만 넣었다.**
relation을 message 안으로 넣은 것이 CompGCN이 처음이고, 그것이 논문 제목의 "Composition-based"다.

## 7. basis와 block을 숫자로

### basis가 왜 basis인가

수학에서 기저(basis)는 "그것들의 조합으로 나머지를 다 만들 수 있는 부품 세트"다. 2차원 평면에서
`[1,0]`과 `[0,1]` 두 개면 모든 2차원 벡터를 만들 수 있다. R-GCN은 이것을 **행렬**에 적용한다.

```
V₁, V₂, V₃  를 만들어둔다      ← basis. 모든 관계가 공유

W 소속 = 0.7·V₁ + 0.2·V₂ + 0.1·V₃
W 재직 = 0.5·V₁ + 0.4·V₂ + 0.1·V₃
        └─────────────────────┘
        관계마다 배우는 건 이 계수뿐
```

다만 진짜 기저는 아니다. 100×100 행렬 전체를 만들려면 부품이 10,000개 필요한데 100개만 둔다.
**일부러 못 만들게 제한하는 것**이 핵심이다.

### 숫자로

d = 100, 관계 1,345개로 계산하면 이렇다.

| | 저장하는 숫자 | 관계 하나가 배우는 숫자 |
|---|---|---|
| 독립 행렬 | 1,345 × 100 × 100 = 13,450,000 | 10,000 |
| basis (B=100) | 기저 1,000,000 + 계수 134,500 = 1,134,500 | **100** |

12배 줄었다. 그런데 요점은 오른쪽 열이다. 관계 하나가 정해야 할 숫자가 10,000개에서 100개로
줄었다.

```
관계 "감수" 로 이어진 엣지가 5 개뿐이다

독립 행렬  →  숫자 10,000 개를 사례 5 개로 정해야 한다.  불가능
basis     →  숫자 100 개만 정하면 된다. 그리고 V₁~V₁₀₀ 은
             "소속"(5만 사례) · "저자"(3만 사례) 가 이미 잘 만들어놨다
```

물감 100통을 공용으로 두고 각 관계는 배합비만 정하는 셈이다. 물감 자체는 데이터가 많은 관계들이
만들어준다.

### block은 무엇이 다른가

direct sum은 행렬을 블록들의 대각 배치로 쓴다는 뜻이다. d = 100, 블록 크기 10이면 블록이 10개다.

```
블록 하나  10 × 10 = 100 개
블록 10 개              1,000 개를 학습
나머지                  9,000 개는 0 으로 못박음
```

규모는 basis와 비슷한데 성격이 다르다.

```
basis   "감수" 는 다른 관계가 만든 부품을 빌려 쓴다     →  사례 5 개로도 된다
block   "감수" 는 여전히 혼자 1,000 개를 정해야 한다    →  사례 5 개면 여전히 안 된다
```

**block은 파라미터만 줄이고 rare relation 문제는 풀지 못한다.** 그리고 블록 밖이 0이라 feature
1과 feature 50이 상호작용해야 하는 관계는 표현되지 않는다.

## 8. 세 가지 방향

**canonical relation은 KG에 실제로 저장된 방향이다.** `(연구자 A, authored, 논문 C)`가 그것이다.
그런데 KG 엣지는 한 방향이고 message passing에서 정보는 양쪽으로 흘러야 한다.

```
논문 C 의 표현을 만들 때    →  누가 썼는지(연구자 A) 를 알아야 한다
연구자 A 의 표현을 만들 때  →  무엇을 썼는지(논문 C) 를 알아야 한다
```

엣지를 그대로 두면 C가 A에게 정보를 보낼 통로가 없다. 그래서 역방향 엣지 `authored_inv`를
인위적으로 만든다.

**R-GCN은 이 둘을 같은 관계로 보지 않는다.** 별도 relation type이라 행렬도 따로다. 두 방향이
담는 정보가 다르기 때문이다.

```
연구자 A 입장에서 논문 C 는     "내가 쓴 것"
논문 C 입장에서 연구자 A 는     "나를 쓴 사람"
```

"내가 쓴 논문들"을 모아 나를 설명하는 방식과 "나를 쓴 저자들"을 모아 나를 설명하는 방식이 같을
이유가 없다. 같은 행렬을 쓰면 두 방향이 구분되지 않아 `authored`가 대칭 관계인 것처럼 학습된다.
슬라이드의 "subject와 object의 역할 차이를 보존"이 이 뜻이다.

self-loop가 따로 있는 이유는 경로가 하나 더 있기 때문이다. 자기 자신이다. 1층에서 만들어진 A의
표현을 2층에서 또 이웃으로만 덮으면 2층의 A는 "이웃의 이웃"으로만 만들어진다. `W_0 h_i`가 그것을
이어준다.

| | 무엇에서 오는 정보 | R-GCN | CompGCN |
|---|---|---|---|
| 정방향 (canonical) | 내가 subject인 엣지 | relation type에 흡수 | W_O |
| 역방향 (inverse) | 내가 object인 엣지 | relation type에 흡수 | W_I |
| 자기 자신 (self-loop) | 이전 층의 나 | W_0 로 따로 | W_S |

CompGCN에서 셋이 나란해진다.

## 9. 평가 지표 계산

[S14A 17절](S14A-R-GCN-관계별-메시지-전달.md)의 예시를 그대로 따라가면 된다.

| Query | 정답 rank | Reciprocal rank |
|---|---|---|
| Q1 | 1 | 1.000 |
| Q2 | 2 | 0.500 |
| Q3 | 10 | 0.100 |

```
MRR      = (1 + 1/2 + 1/10) / 3 = 0.533
Hits@1   = 1 / 3 = 0.333
Hits@3   = 2 / 3 = 0.667
Hits@10  = 3 / 3 = 1.000
```

MRR은 rank 1과 rank 2의 차이(1 → 0.5)를 rank 9와 rank 10의 차이(0.111 → 0.1)보다 훨씬 크게
본다. 상위 순위를 중시하는 지표다.

Filtered는 평가 대상 말고 이미 참으로 알려진 답을 후보에서 빼는 것이다. `(Seoul, capitalOf, ?)`를
평가하는데 다른 정답이 후보에 남아 있으면 그것이 위로 올라가 정답 순위가 부당하게 밀린다.

## 10. 실험 파트 읽는 법

### 실험이 답하려는 질문부터 본다

논문의 실험은 "우리 모델이 좋다"를 보이는 것이 아니라 **질문 하나에 답하는 것**이다. R-GCN의
질문은 [S14A 4절](S14A-R-GCN-관계별-메시지-전달.md)에 이미 적혀 있다. "local structure의 효과를
검증한다"이고, 그 답은 21절 하나에 있다. 나머지 표는 조건과 맥락이다.

### 데이터셋 표는 조건을 말한다

숫자 자체가 아니라 "이 실험이 어떤 조건에서 이뤄졌나"를 읽는다.

```
S14A 18절   Labeled 줄     BGS 는 entity 333,845 개 중 label 146 개 (0.04%)
                           → 지도학습만으로는 안 된다. GNN 을 쓸 이유가 데이터에 있다

S14A 19절   Relations 줄   FB15k 는 1,345 개
                           → 8절의 파라미터 문제가 이론이 아니라는 증거
```

18절 마지막 항목의 "label 생성에 쓰인 relation을 제거한다"도 조건이다. AIFB에서 `employs`를
남겨두면 모델이 그 엣지 하나만 보고 맞힌다. 구조 학습을 평가하는 것이 아니게 된다.

### raw와 filtered

같은 R-GCN인데 [S14A 22절](S14A-R-GCN-관계별-메시지-전달.md) 표에서 0.158(raw)과 0.248(filtered)로
다르다.

raw는 후보에 다른 정답이 섞인 채로 잰 값이다. `(Seoul, capitalOf, ?)`를 평가하는데 후보에 다른
정답이 남아 있으면 그것이 위로 올라가 정답 순위가 부당하게 밀린다. **filtered가 실제 성능에
가깝고 논문 비교는 filtered로 한다.** 표에서 볼 열은 `MRR filtered` 하나다.

### 표의 각 행이 왜 있는지가 다르다

성능 비교용이 아닌 행이 섞여 있다.

| 행 | 왜 있나 |
|---|---|
| LinkFeat 0.063 | 관측된 링크만 보는 단순 baseline |
| DistMult 0.191 | 21절의 A 조건. encoder 없는 같은 decoder |
| R-GCN 0.248 | 21절의 B 조건 |
| TransE · ComplEx | 그 시절의 다른 계열 |

**LinkFeat 행은 데이터셋 검증용이다.** 원래 FB15k에서는 이 단순 baseline이 정교한 모델들을 다
이겼다. 역관계 쌍이 남아 있어 "이미 이어져 있나"만 봐도 맞힐 수 있었기 때문이다. FB15k-237에서
0.063으로 무너졌다는 것은 데이터셋 정리가 실제로 작동했다는 증거다.

### 변인 통제

[S14A 21절](S14A-R-GCN-관계별-메시지-전달.md)이 이 논문에서 가장 중요한 자리인 이유다.

```
A. entity 벡터 = 자유 파라미터   → DistMult → 0.191
B. entity 벡터 = encoder 출력    → DistMult → 0.248
```

decoder도 같고 relation 대각벡터도 양쪽 다 학습한다. 다른 것이 하나뿐이므로 차이를 그 하나의
몫으로 돌릴 수 있다. **하나만 바꾸고 나머지를 고정하는 것**을 변인 통제라 한다.

### 열 단위로 읽어야 하는 표

[S14B 11절](S14B-CompGCN-합성-기반-관계-표현.md)의 Table 4가 그렇다.

```
                  TransE   DistMult   ConvE
X (encoder 없음)   0.294    0.241     0.325     ← 각 열의 기준선
X + R-GCN         0.281    0.324     0.342
X + CompGCN(Corr) 0.336    0.335     0.355
```

행끼리 가로로 비교하면 안 된다. 열마다 decoder가 다르기 때문이다. **같은 열 안에서만 비교가
성립한다.** ConvE 열에서 encoder 없이 0.325, R-GCN 0.342, CompGCN 0.355로 읽는다.

### ± 는 표준편차

여러 번 돌린 결과가 얼마나 흔들리는지를 나타낸다.
[S14B 14절](S14B-CompGCN-합성-기반-관계-표현.md)에서 이 값이 결론을 바꾼다.

```
MUTAG (Graph)   PATCHY-SAN 92.6 ± 4.2      CompGCN 89.0 ± 11.1
```

차이가 3.6인데 표준편차가 11.1이다. **차이가 흔들림 안에 들어가므로 우열을 단정할 수 없다.**
반면 node classification 쪽은 ±1.2, ±0.2로 작아서 85.3과 90.6은 믿을 만하다. 같은 표에서
node 결과는 "strong"이고 graph 결과는 "mixed"인 이유가 이것이다.

### 그림 여럿이 한 주장을 받치는 경우

[S14B 13절](S14B-CompGCN-합성-기반-관계-표현.md)의 Figure 3·4·5가 그렇다. 따로 보면 무슨 얘기인지
잡히지 않는데 셋을 합치면 하나의 주장이 된다.

| | 묻는 것 | 답 |
|---|---|---|
| Figure 3 | basis를 줄여도 성능이 유지되나 | 5개까지 줄여도 97.2% |
| Figure 4 | 같은 relation 수에서 R-GCN보다 나은가 | 전 구간에서 CompGCN이 위 |
| Figure 5 | relation 수가 달라져도 유지되나 | 유지됨 |

합치면 "relation matrix보다 relation basis vector가 효율적이다"가 된다.

### Limitation 칸은 다음 논문의 목차다

[S14A 23절](S14A-R-GCN-관계별-메시지-전달.md)의 Takeaway 표에서 Limitation 칸을 읽으면 CompGCN이
무엇을 할지가 그대로 나온다.

```
relation 마다 matrix 가 필요해 확장성이 낮음     →  CompGCN 이 벡터로 낮춘다
업데이트되는 representation 이 entity 에 한정   →  CompGCN 이 relation 도 갱신한다
rare relation 의 학습이 여전히 불안정           →  relation basis vector
```
