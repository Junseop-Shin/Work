## 1. Ontology Learning의 여섯 단계

corpus에서 시작해 온톨로지 구조로 올라가는 순서다. Ch.2의 Layer Cake와 같은 층위인데, 이
회차는 그것을 여섯 개의 예측 문제로 다시 쓴다.

| 단계 | 하는 일 | 이 논문 |
|---|---|---|
| 1 Corpus | 도메인 문서를 모은다 | 평가 안 함 |
| 2 Terms | 용어 후보를 뽑는다 | 평가 안 함 |
| 3 Types | 용어에 타입을 붙인다 | **Task A** |
| 4 Taxonomy | 타입 사이의 상하 관계를 세운다 | **Task B** |
| 5 Relations | 타입 사이의 그 밖의 관계를 붙인다 | **Task C** |
| 6 Axioms | 제약과 논리 규칙을 붙인다 | 평가 안 함 |

아래로 갈수록 형식이 강해지고 사람 손이 더 든다. 이 논문이 실증하는 것은 가운데 셋이다.

## 2. term typing이란 무엇인가

`typing`은 "이 낱말이 어떤 종류인가"를 붙이는 일이다. 분류(classification)와 같은 말인데,
붙이는 라벨이 온톨로지의 클래스라서 typing이라 부른다.

```
myocardial infarction   →   Disease or Syndrome
Seoul                   →   populated place
```

**여기서 중요한 것은 정답 라벨 집합이 이미 정해져 있다는 점이다.** 새 타입을 만들어내는 일이
아니라, 주어진 label space에서 하나를 고르는 일이다. 그래서 label space의 크기가 난이도를
지배한다. WordNet은 4개(명사·동사·형용사·부사) 중 하나를 고르고, GeoNames는 680개 중 하나를
고른다.

## 3. 네 개의 지식원

| | 무엇인가 | 타입의 성격 |
|---|---|---|
| WordNet | 영어 낱말을 의미 단위(synset)로 묶은 어휘망 | 품사 4종 |
| GeoNames | 전 세계 지명 데이터베이스 | 위치 유형 680종 (도시·강·산…) |
| UMLS | 미국 국립의학도서관의 의학 용어 통합 체계 | semantic type 127종 |
| schema.org | 웹페이지 구조화 데이터용 공용 어휘 | Thing 아래 797종 |

성격이 일부러 다르다. 일반 어휘(WordNet), 고유명사 중심(GeoNames), 전문 도메인(UMLS), 웹
실무 표준(schema.org)이다. 네 곳에서 같은 방법이 통하는지를 보려는 설계다.

## 4. semantic type과 개별 엔티티는 다른 층이다

UMLS에서 `myocardial infarction`은 개별 개념이고 `Disease or Syndrome`(T047)은 그 개념이 속한
semantic type이다. `T047` 같은 번호가 semantic type의 식별자다.

Task A는 개념에서 semantic type으로 올라가는 일이고, **Task B와 C는 semantic type끼리의 관계**다.
`Pathologic Function → Disease or Syndrome`은 개별 질병 둘의 관계가 아니라 타입 둘의 관계다.

층을 헷갈리면 Task B가 쉬워 보인다. 실제로는 127개 타입 사이의 상하 관계를 묻는 것이라
도메인 지식이 필요하다.

## 5. taxonomy의 방향과 transitive closure

taxonomy는 is-a 관계로 만든 계층이고 **방향이 있다.** `A is the superclass of B`는 A가 위,
B가 아래라는 뜻이다.

`A → B`이고 `B → C`이면 `A → C`도 참이다. 이것을 transitive closure라 한다. 이 논문은 직접
연결된 쌍뿐 아니라 이렇게 유도된 쌍도 positive로 쓴다.

negative는 알려진 부모–자식 쌍의 **방향을 뒤집어** 만든다. 존재하지 않는 쌍을 아무거나 가져오는
것보다 어렵다. 두 타입이 실제로 관계가 있다는 것은 맞고 방향만 틀리기 때문이다.

## 6. non-taxonomic relation

is-a가 아닌 나머지 관계를 통틀어 부르는 말이다. `treats`, `causes`, `locatedIn` 같은 것들이다.

taxonomy와 갈라 부르는 이유는 난이도가 다르기 때문이다. is-a는 어휘 의미만으로도 상당 부분
풀리지만, `치료한다`는 세상 지식이 있어야 한다.

## 7. cloze와 prefix — 모델 계열이 프롬프트를 가른다

[S22-1 4절](S22-1-읽는-데-필요한-것들.md)에서 COMET이 GPT이고 WKLM이 BERT인 이유를 봤다.
같은 구분이 여기서 프롬프트 형식을 가른다.

| | 학습 방식 | 프롬프트 |
|---|---|---|
| Encoder (BERT) | 가린 토큰 복원 | cloze — `[L] is a [MASK].` 빈칸을 채우게 한다 |
| Decoder-only (GPT) | 다음 토큰 예측 | prefix — 문장을 주고 이어 쓰게 한다 |
| Encoder–decoder (BART·Flan-T5) | 입력을 출력 문장으로 변환 | 둘 다 가능 |

같은 질문인데 모델에 따라 문장 모양이 달라진다. 그래서 "어느 모델이 더 낫다"는 비교에는
프롬프트 형식 차이가 섞여 있다.

## 8. zero-shot · fine-tuning · instruction tuning

| | 무엇을 하나 |
|---|---|
| zero-shot | 학습된 모델을 그대로 쓴다. 가중치를 건드리지 않는다 |
| fine-tuning | 과제 예제로 가중치를 다시 조정한다 |
| instruction tuning | 여러 과제를 "지시문 + 답" 형태로 미리 학습시켜 지시를 따르게 만든다 |

**Flan-T5**가 instruction tuning을 거친 T5다. 이 논문이 fine-tuning 대상으로 Flan-T5를 고른
이유는 공개 모델이고 지시문을 이미 이해하기 때문이다. GPT-4는 가중치를 못 만지니 zero-shot에만
쓴다.

## 9. MAP@1

Mean Average Precision at 1이다. 이름은 거창한데 하는 일은 간단하다. **term마다 1순위로 예측한
타입이 정답 라벨과 맞는지를 보고 전체 평균을 낸다.**

`@1`이라 top-1 정확도와 사실상 같다. 정답이 여러 표기(synonym)를 가질 수 있어 accepted label
집합과 대조한다는 점만 다르다.

Hits@K와 다른 점은 순위를 여러 개 보지 않는다는 것이다. 온톨로지 타입은 하나로 정해져야
쓸모가 있어서 1순위만 본다.

## 10. correct / incorrect 두 클래스에서 F1 읽기

Task B·C는 이진 판정이다. 이때 Macro-F1은 **correct 클래스의 F1과 incorrect 클래스의 F1을
따로 내서 평균**한 값이다.

한쪽으로만 답하는 모델을 걸러내기 위해서다. 전부 correct라고 답하면 correct 클래스의 recall은
1.0이지만 incorrect 클래스의 recall은 0이라 Macro-F1이 0.5 근처로 떨어진다.

그래서 이 지표를 보려면 **positive와 negative의 비율**을 함께 봐야 한다. Task C 공개 데이터는
positive 5,641 · negative 1,896으로 3:1이다.

## 11. type-aware negative sampling

Task C의 negative는 아무 트리플이나 가져오는 것이 아니라 **타입을 맞춰 뽑는다.** 이 장치는
이 강의에서 세 번째로 나오는 것이다.

| 회차 | 어디에 썼나 |
|---|---|
| S13 TransE | 가짜 트리플을 만들 때 같은 타입 안에서 바꾼다 |
| S22 WKLM | 치환할 가짜 엔티티를 같은 타입 풀에서 고른다 |
| S23 Task C | 후보 트리플의 negative를 타입을 맞춰 뽑는다 |

이유도 같다. 타입이 안 맞으면 모델이 지식 대신 표면 단서로 풀어버린다. 자세한 것은
[S22-1 11절](S22-1-읽는-데-필요한-것들.md)과 01 문서 2절에 있다.

## 12. best-prompt reporting과 validation split

머신러닝에서 데이터를 셋으로 나눈다. 학습(train), 검증(validation), 평가(test)다. 하이퍼파라미터나
프롬프트처럼 **사람이 고르는 것은 validation에서 골라야** 한다. test에서 고르면 그 test 점수는
더 이상 일반화 성능이 아니다.

이 논문은 Task A·B에서 프롬프트를 최대 8개 시도하고 **test 최고점을 대표값으로 보고**한다.
validation split을 따로 두었다는 언급이 없다.

슬라이드도 이것을 `Critical note`로 적어뒀다. 숫자를 읽을 때 "8번 시도한 것 중 가장 좋은 것"을
보고 있다는 점을 감안해야 한다.

## 13. pretraining exposure

평가에 쓴 WordNet·UMLS·schema.org는 공개 자원이라 **모델이 사전학습 때 이미 봤을 수 있다.**
그러면 zero-shot 성능이 실제 추론 능력인지 기억인지 구분되지 않는다.

정리 슬라이드가 이것을 남은 한계로 적고 있다. 이 문제는 LAMA 계열 probing 연구에서 반복해서
지적돼 온 것이고([S20-1 10절](S20-1-읽는-데-필요한-것들.md)), 공개 벤치마크를 쓰는 한 완전히
피하기 어렵다.
