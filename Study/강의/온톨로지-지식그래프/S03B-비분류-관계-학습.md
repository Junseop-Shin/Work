## 한 줄 요약

비분류 관계(`R* ⊆ C × C × string`)는 **개념쌍을 찾는 것과 관계에 이름을 붙이는 것** 두 일이다.
이 논문은 **동사구를 관계 라벨로 쓰고**, **웹을 코퍼스로 삼아** 도메인 키워드 하나에서 온톨로지를
from scratch로 만든다. 다만 **정답지가 없어서** WordNet gloss-vector로 대리 채점하는데,
그 대리 채점 자체가 이 논문의 가장 약한 고리로 남는다.

---

## 1. Non-taxonomic relationship 학습의 필요성

**Motivation**

- Ontology = concept **C** + taxonomic **H** (IS-A) + non-taxonomic **R\***
- 기존 ontology 연구는 대부분 **C, H에 집중됨** → **R\* 학습이 필요함**

**Challenge**

- **어떤 유형의 관계가, 몇 개가 필요한지 미리 알기가 어려움**
  - 어떤 개념이 연결되는지를 **탐지**해야 하며,
  - 그 관계에 **labeling**을 해야 함 ← **본 논문이 집중하는 point**

**Approach**

- **Web을 하나의 코퍼스로 활용** → 방대하고 중복이 많은 용어·관계로 **실제 knowledge 분포를 근사**
- **Verb를 관계 label로 활용** → web-scale statistics로 개념 및 관계를 선별
- **Automatic · Unsupervised · Domain Independent**한 온톨로지 구축 방법론 제안

## 2. 전체 프레임워크

**목표: 도메인 온톨로지를 from scratch로 구축**

- **Domain keyword 하나에서 출발** (ex. `cancer`)
- **Incremental & Iterative**: 한 단계의 결과를 다음 단계의 입력으로 사용 (recap. layer cake)

**파이프라인**

| 단계 | 내용 |
|---|---|
| **Taxonomic learning** (선행 연구 활용) | Domain keyword(Terms) → IS-A 관계(Concept Hierarchies) 구축 · **Domain Verb candidates 수집** |
| **Non-taxonomic learning** (본 논문의 핵심) | 동사 목록, 키워드를 바탕으로 비분류 관계 파악 및 라벨링 |
| **Recursive learning** | 구축한 개념을 **새 seed**로 하여 다단계 구조로 확장 (암 → 폐암 → …) |
| **Post-processing** | 중복 제거, 암묵적인 관계 정리하여 최종 **OWL** 온톨로지 구축 |

```
  Domain Keyword  (ex. cancer)
         │
         ▼
  ┌─────────────────────────┐        ┌──────────────┐
  │   Taxonomic learning    │ ◀────▶ │  Web Search  │
  │     (선행 연구 활용)      │        │    Engine    │
  └─────────────────────────┘        └──────────────┘
         │                                   ▲
         ├──▶ Concept Hierarchies (IS-A)      │
         └──▶ Domain Verb Candidates          │
                      │                       │
                      ▼                       │
  ┌───────────────────────────────┐           │
  │  Non-taxonomic learning       │ ◀─────────┘
  │  ① Verb Extraction & Selection│
  │  ② Retrieval & Selection      │
  │     of Related Concepts       │
  └───────────────────────────────┘
                      │  non-taxonomic relationships
                      ▼
  ┌───────────────────────────────┐
  │        Post-processing        │   중복 제거 · 암묵 관계 정리
  └───────────────────────────────┘
                      │
                      ▼
           OWL Domain Ontology

  ↺ Recursive learning — 얻은 concept을 새 Domain Keyword로 넣어 반복
                          (cancer → leukaemia → …)
```

**Taxonomic 단계가 동사 후보까지 같이 수집한다는 게 설계의 요령이다.** IS-A 계층을 만들며 훑은
문맥에서 동사구를 함께 건져두므로, 비분류 단계가 빈손으로 시작하지 않는다.
그리고 **웹 검색엔진이 두 단계 모두에 붙는다** — 계층을 만들 때도, 관계를 찾을 때도 코퍼스가 웹이다.

## 3. Non-taxonomic Learning ① — Verb Extraction and Selection

### 3.1 Why verb?

- 비분류 관계는 **동사로 표현되기에**, 이를 label로 사용
- 그러나 **동사는 무수히 많기에** → **도메인에 관련된 주요 동사만 선택해야 함**

### 3.2 Step 1. Verb Phrase 추출 (linguistic filtering)

- Taxonomic 단계에서 **keyword 문맥에 등장한 verb phrase 수집** (OpenNLP: POS tagging + chunking 라이브러리)
- **현재 시제만** 추출
- 제외·처리 규칙
  - 부사 제외 — `tends to develop in`
  - 복합 동사 제외
  - 전치사 부착
  - **taxonomic 동사 제외** — `is` / `are` / `include` → **IS-A 관계를 나타내기에**
- **키워드 위치에 따른 역할 분류: predecessor / successor**

```
____ causes hypertension          →  PRE  (키워드가 뒤)
Hypertension is treated with ____ →  SUC  (키워드가 앞)
```

같은 동사가 PRE/SUC 양쪽에 따로 등재된다(`causes`가 PRE·SUC 둘 다 목록에 있다).
**방향이 곧 관계의 의미**이기 때문이다.

### 3.3 Step 2. 통계 기반 Verb 선택

Web-scale statistics 기반 verb phrase의 **domain-specificity** 계산:

```
Score(verb phrase, keyword) = hits("vp kw") / hits("vp")
```

- 키워드와 verb phrase가 **얼마나 자주 겹치는지** 확인
- Successor의 경우, vp와 kw의 위치를 바꿈

> 다행히 도메인 특이도 점수가 이들을 아래로 밀어내지만, **노이즈의 성격이 코퍼스의 성격을 따라온다**는 건 기억할 만하다.

## 4. Non-taxonomic Learning ② — Retrieval and Selection of Related Concepts

### 4.1 Step 1. 패턴 기반 concept 후보 추출

- 선택된 **verb phrase + keyword**로 **web query 패턴** 구성

```
"____ is associated with hypertension"     (PRE)
"hypertension is caused by ____"           (SUC)
```

- 검색 결과에서 **패턴 앞뒤의 concept을 추출**
- **Text nugget 제약**: 단순 문장 형태만 허용 — `[NP] + [VP] + [NP]`

### 4.2 Step 2. 통계 기반 concept 선택

```
Score(C, kw) = hits("kw AND C") / hits("C")
```

- **AND 조건**으로, 같은 문장이 아닌 **전체 문서 내에서의** score 계산
- **Threshold 이상만** 온톨로지에 추가

```
high sodium diet  +  [is associated with]  +  hypertension     (score: 0.512)
    :concept            :verb phrase            :keyword
```

**두 단계의 통계가 서로 다른 것을 잰다.** 3.3절은 *동사가 이 도메인 것인가*(패턴 필터),
4.2절은 *이 개념이 키워드와 실제로 관련 있는가*(내용 필터)다. 패턴은 문장 단위로 좁게,
관련성은 문서 단위로 넓게 잰다.

## 5. 실전 이슈

### 5.1 Bootstrapping

이미 얻은 지식(상위개념 · 동사 목록)을 **다음 검색에 재사용**한다.

- Keyword인 `cancer` 바탕으로 Concept인 `leukaemia` 추출
- 이후 `leukaemia`를 keyword로 새 concept을 추출하고 싶으면:

```
"leukaemia is related with" AND "cancer"    →  문맥 고정 (다의어 방지)
```

- **하위개념은 상위개념의 동사 목록을 상속** → 검색 횟수 절감

> 상위개념의 동사 목록을 물려받는다는 건 [S02 7.1절](S02-설계-원칙.md)에서 정리한 **"상속으로 비용을 줄인다"**가
> 자동 구축 안에서도 똑같이 쓰인다는 뜻이다. 다만 여기서 상속되는 건 axiom이 아니라 **검색 패턴**이다.

### 5.2 Efficient access to the web content

- **검색엔진 조합**: Google → 리소스 추출 / MSNSearch → 통계 계산
- **전체 페이지 대신 snippet 분석** — 페이지 1개 파싱 ≈ 웹사이트 50개 접근 효과

### 5.3 Adaptive corpus size

- **Learning rate** = 추출된 concept 후보 중 **선별된 비율**
- 50개씩 늘려가며 분석 → **learning rate가 threshold 아래로 떨어지면 중단**
- **생산적인 동사 패턴은 분석하고, 비생산적인 건 조기 종료**

Fig. 5 결과 (Hypertension, threshold 60%):

| 패턴 | 경과 |
|---|---|
| `suffer from hypertension` | 웹 리소스 50개에서 **0%로 급락** → 즉시 종료 |
| `is associated with hypertension` | 100개까지 **100% 유지**, 350개에서 threshold 도달 |
| `hypertension is caused by` | 80% 부근에서 완만히 하락 |
| `hypertension is associated with` | 200개 부근에서 threshold 아래로 |

**패턴별로 수확이 끝나는 시점이 크게 다르다.** 그래서 코퍼스 크기를 전역으로 정하지 않고
패턴별로 적응시킨다.

## 6. Evaluation — WordNet 기반 자동 평가

### 6.1 비분류 관계는 정답지가 없다

- **비분류 관계를 담은 gold standard는 거의 존재하지 않음**
- 결과의 양도 방대하기에 수작업 평가는 비현실적 → **자동 평가 절차 설계가 필요함**

> [S03A 8절](S03A-용어-추출-P-Mod.md)의 Paper 1은 UMLS Metathesaurus를 정답지로 쓸 수 있었다.
> **Relations 층에는 그런 게 없다.** 같은 저자 그룹이 아니어도 같은 벽에 부딪히는데,
> 이 차이가 두 논문의 평가 신뢰도를 갈라놓는다.

### 6.2 WordNet의 gloss-vector relatedness

- **WordNet**: 영어 어휘 사전. 각 개념(synset)마다 **정의문(gloss)**이 제공됨
  - Synset = 동의어 집합 — 자동차: `{car, auto, automobile, machine, motorcar}`
  - Gloss = synset의 정의문 — *"a motor vehicle with four wheels; usually propelled by an internal combustion engine"*
- **Gloss-vector**: 두 개념의 **gloss를 벡터화하여 코사인 유사도**를 계산
  - **Taxonomic이 아닌, 관계 전반의 relatedness 측정에 적합**

### 6.3 평가 방식

- 앞서 추출한 **keyword-concept 쌍**을 gloss-vector 기준으로 대조
  - `high sodium diet` + [is associated with] + `hypertension`
- **같은 threshold에서 논문 방법 / gloss-vector의 선별 및 기각이 일치하는지** 확인
- 지표: Precision, Recall, F-measure

## 7. Evaluation of non-taxonomic relationships

**3-Domain Result** (행 = 논문 방법의 판정 / 열 = WordNet의 판정)

| 도메인 | | WordNet Right | WordNet Wrong | 합계 |
|---|---|---|---|---|
| **Cancer** | Selected | **99** (TP) | 23 (FP) | 122 |
| | Rejected | 1 (FN) | 1 (TN) | 2 |
| **Sensor** | Selected | 52 | 16 | 68 |
| | Rejected | 11 | 24 | 35 |
| **Hypertension** | Selected | 76 | 68 | 144 |
| | Rejected | 106 | 61 | 167 |

| 도메인 | Precision | Local Recall | Local F-measure |
|---|---|---|---|
| Cancer | 약 80% | 약 100% | 약 89% |
| Sensor | 약 76% | 약 68% | 약 72% |
| Hypertension | 약 53% | 약 55% | 약 54% |

**성능이 좋지 않은 것은 방법론 자체의 문제가 아닌 WordNet의 문제라는 게 논문의 해명이다.**

- **Sensor**: 전체의 **40%만 평가가 가능**했음 (나머지 60%의 concept이 WordNet에 없었음)
- **Hypertension 성능 저조 원인**: Gloss-vector가 **WordNet 커버리지에 의존**

증거로 든 예:

```
atherosclerosis(동맥경화)  ↔  hypertension(고혈압)

의학적으로 밀접하게 관련됨 (고혈압이 동맥경화를 유발)
그러나 gloss-vector 점수는 0.04  ← 동맥경화의 gloss에 고혈압이 언급되지 않음
그러나 논문의 웹 기반 점수는 0.47
```

이 예는 설득력이 있다 — gloss는 **정의문 한 줄**이므로 그 안에 언급되지 않은 관계는
전부 0점이 된다. 관계를 재는 도구로 쓰기엔 구조적으로 부족하다.

## 8. Conclusion & Comments

**Contribution**

- **Verb Phrase를 관계 label로 활용** → **기존 연구가 소홀히 한 labeling 문제를 해결**
- Web + Web-scale statistics로 비분류 관계를 **unsupervised · automatic · domain independent**하게 발견
- **기존 ontology 없이 from scratch 구축**

**Comments** (발표자의 비평)

- **핵심 기여인 verb label의 정확성은 결국 평가에서 빠짐** — concept-keyword 쌍만 채점할 수 있음
- 평가 기준이 **WordNet에 의존**함
- **다의어, 동의어 처리에 어려움**이 존재함

> 첫 항목이 가장 아프다. 논문의 기여가 "관계에 이름을 붙였다"인데, gloss-vector는 **개념쌍의 관련성만**
> 재고 **그 이름이 맞는지는 못 잰다.** `hypertension is caused by X`와 `hypertension is treated with X`가
> 같은 점수를 받는다. 즉 **기여와 평가가 어긋나 있다.**

## 9. Takeaway — 다른 layer, 같은 원리

> **언어적 기법으로 후보를 선택하고, 통계적 기법으로 최종 결정을 진행함**
