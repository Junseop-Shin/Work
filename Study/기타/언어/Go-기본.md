# Go 기본 — 타입·구조체·인터페이스·에러

> 2026-06-08 | Go, 타입시스템, 인터페이스, 에러처리, 슬라이스

## 한 줄 요약

Go는 **명시성과 단순함을 강제하는 정적 타입 언어**로, 상속·예외·제네릭 남용 같은 "숨은 제어 흐름"을 의도적으로 제거하고, 값 의미론 / 암묵적 인터페이스 / 에러-값 반환을 통해 코드의 동작을 표면에 드러내도록 설계됐다.

## 핵심 개념

### 왜 Go인가

해결하려는 문제는 "대규모 협업에서의 코드 단순성과 동시성"이다.

- **숨은 비용 제거**: 예외(숨은 throw 경로), 상속(깊은 계층), 연산자 오버로딩 등을 빼서 "코드를 보면 동작이 보이게".
- **빠른 컴파일 + 단일 바이너리**: 의존성을 정적 링크한 하나의 실행파일 → 배포가 단순.
- **동시성 1급 지원**: `go`, `channel`, `select`가 언어 키워드 ([Go 동시성](Go-동시성.md) 참고).

비교 대상: C++/Java의 복잡성에 대한 반작용. "기능을 더하기보다 빼서 단순함을 지킨다"가 철학.

### 타입 시스템 — 값 타입 vs 참조성

```go
arr := [3]int{1, 2, 3}   // 배열: 값 타입 → 복사됨
s   := []int{1, 2, 3}    // 슬라이스: 참조성(헤더 복사)
m   := map[string]int{}  // 맵: 참조 타입
```

- **배열은 값**이다. 함수 인자로 넘기면 통째로 복사된다. 그래서 실무에서는 거의 항상 슬라이스를 쓴다.
- **zero value**: 선언만 해도 0값으로 초기화된다. `int→0`, `bool→false`, `string→""`, 포인터/슬라이스/맵/채널/인터페이스/함수→`nil`. "초기화 안 된 상태"가 존재하지 않는다(Java의 미초기화 NPE 없음).

#### 슬라이스 내부 구조 (가장 중요)

슬라이스는 `{ptr, len, cap}` 3-워드 헤더다.

- `ptr`: 백킹 배열을 가리키는 포인터
- `len`: 현재 길이
- `cap`: 백킹 배열의 끝까지 용량

```go
s := make([]int, 2, 5)  // len=2, cap=5
```

복사해도 **같은 백킹 배열**을 가리키므로 한쪽 수정이 다른 쪽에 보인다.

⚠️ **append의 이중성** — cap을 넘으면 새 배열로 재할당되어 원본과 끊기고, 안 넘으면 원본을 공유한다.

```go
a := []int{1, 2, 3}
b := a[:2]            // b: len=2, cap=3 (a와 백킹 공유)
b = append(b, 99)    // cap 안 넘음 → a[2]가 99로 덮어써짐!
// a == [1 2 99]
```

이 "공유되다가 어느 순간 끊김"이 Go 슬라이스 버그의 단골이다. 독립 복사가 필요하면 `copy()` 또는 `slices.Clone()`.

### 구조체 & 메서드 — 상속이 없다

```go
type Animal struct{ Name string }

func (a Animal)  Speak() string { return a.Name } // 값 리시버
func (a *Animal) Rename(n string) { a.Name = n }  // 포인터 리시버
```

#### 값 리시버 vs 포인터 리시버

| | 값 리시버 `(a Animal)` | 포인터 리시버 `(a *Animal)` |
|---|---|---|
| 동작 | 복사본을 받음 | 원본을 가리킴 |
| 상태 변경 | 불가(복사본만 바뀜) | 가능 |
| 큰 구조체 | 복사 비용 발생 | 복사 없음 |

관례: **한 타입의 메서드 집합은 값/포인터 중 하나로 통일**한다(혼용 시 메서드셋 규칙이 헷갈림).

#### 임베딩 = 상속이 아니라 합성 + 자동 승격

```go
type Dog struct {
    Animal        // 임베딩 (필드 이름 없음)
    Breed string
}
d := Dog{Animal{"Rex"}, "Shiba"}
d.Speak()         // Animal의 메서드가 "승격(promotion)"되어 바로 호출
d.Name            // d.Animal.Name 도 바로 접근
```

- 이것은 `is-a`(상속)가 아니라 `has-a`(합성) + 위임이다.
- 오버라이드처럼 보이지만 실제로는 바깥 타입에 같은 이름 메서드가 있으면 그게 우선될 뿐(메서드 해석 규칙).

### 인터페이스 — 암묵적 구현

```go
type Speaker interface { Speak() string }
// Dog는 implements 키워드 없이도 Speak()만 있으면 자동으로 Speaker
var s Speaker = d
```

- **`implements` 선언이 없다.** 메서드 시그니처만 만족하면 자동으로 그 인터페이스다(정적 덕 타이핑).
- 그래서 **인터페이스를 쓰는 쪽에서 정의**하는 문화가 생긴다 → "작은 인터페이스"(`io.Reader`는 메서드 1개).
- 인터페이스 값의 내부 = **`(타입, 값)` 2-워드 튜플**.

⚠️ **nil 인터페이스 ≠ nil (악명 높은 함정)**

```go
func doThing() error {
    var p *MyError = nil
    return p           // ❌ 타입(*MyError)이 들어가 있어 인터페이스는 non-nil!
}
if err := doThing(); err != nil {
    // 여기 진입함! p는 nil인데도.
}
```

인터페이스는 타입 정보가 채워지면, 값이 nil이어도 인터페이스 자체는 nil이 아니다. 에러를 nil 포인터로 반환할 때 터지는 단골 버그. → 에러는 `nil`을 직접 반환하라.

### 에러 처리 — 예외가 없다

```go
f, err := os.Open("x")
if err != nil {
    return fmt.Errorf("열기 실패: %w", err)  // %w로 래핑
}
defer f.Close()
```

- **에러는 그냥 값**(`error` 인터페이스). `try/catch` 없이 `if err != nil`을 반복한다.
  - 장점: 모든 실패 경로가 코드에 명시적으로 드러남.
  - 단점: 장황함(보일러플레이트).
- **래핑/언래핑**:
  - `fmt.Errorf("...: %w", err)` → 원인 에러를 감싸 체인 구성.
  - `errors.Is(err, target)` → 센티넬 에러 비교(예: `os.ErrNotExist`).
  - `errors.As(err, &target)` → 특정 타입으로 추출.
- **`panic`/`recover`**: 예외와 비슷하지만 **정말 복구 불능 상황**에만 쓴다. 일반 에러 흐름에 쓰면 안티패턴.

```go
defer func() {
    if r := recover(); r != nil { log.Println("복구:", r) }
}()
```

#### 왜 예외를 안 쓰나

"에러는 예외적 사건이 아니라 정상 제어 흐름의 일부"라는 철학. 숨은 throw 경로를 없애 코드 추적성을 높인다. 대신 장황함은 감수한다.

## 핵심 질의응답

**Q. 슬라이스를 잘라서 append 했는데 원본이 바뀌었다. 왜?**
A. 슬라이스는 `{ptr,len,cap}` 헤더라 백킹 배열을 공유한다. cap을 넘지 않는 append는 원본 배열의 다음 칸을 덮어쓴다. 독립이 필요하면 `slices.Clone()`.

**Q. 임베딩은 상속인가?**
A. 아니다. 합성(has-a) + 메서드/필드 자동 승격이다. 겉보기엔 상속 같지만 타입 관계(is-a)가 성립하지 않는다.

**Q. 에러로 nil 포인터를 반환했는데 `err != nil`이 참이다. 왜?**
A. 인터페이스는 `(타입,값)` 2-워드다. 타입이 채워지면 값이 nil이어도 인터페이스는 non-nil. 에러는 `nil` 리터럴을 직접 반환해야 한다.

**Q. 왜 Go는 예외(try/catch)를 안 쓰나?**
A. 숨은 제어 흐름을 제거해 코드를 보면 동작이 보이게 하려는 설계. 에러를 값으로 다뤄 모든 실패 경로를 명시한다.

## 주의사항 / 자주 하는 실수

- **슬라이스 cap 공유** — 잘라 쓴 슬라이스에 append하면 원본 오염 가능. `copy`/`Clone`으로 끊어라.
- **nil 인터페이스 함정** — nil 포인터를 인터페이스로 반환하지 마라.
- **Mutex/큰 구조체 값 복사** — 메서드 리시버/인자에서 의도치 않은 복사 주의(`go vet`).
- **`defer`는 함수 종료 시 실행** — 루프 안에서 `defer`하면 루프 끝이 아니라 함수 끝에 몰려 실행됨(리소스 누수).
- **map은 nil이면 읽기는 OK, 쓰기는 panic** — `make`로 초기화 필요.
